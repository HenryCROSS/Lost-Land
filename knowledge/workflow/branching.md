# 分支与提交约定

## 分支策略

采用**主干 + 短生命周期特性分支**。不设 `develop`——阶段划分本身已提供足够的隔离层次，再加一层只会增加合并成本。

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 集成分支 | **必须始终可构建、测试全绿**。不直接提交 |
| `phase/pN-<名称>` | 阶段主线 | 每个阶段一条，如 `phase/p0-platform` |
| `feat/<crate>-<主题>` | 阶段内并行任务 | 从所属阶段分支切出，如 `feat/ll-render-atlas` |
| `fix/<主题>` | 缺陷修复 | 可直接从 `main` 切出 |
| `docs/<主题>` | 纯文档变更 | 可直接从 `main` 切出 |

### 并行开发的关键

**crate 边界即任务边界。** 一条 `feat/` 分支原则上只动一个 crate，这样并行工作的组员不会互相踩。

若某个任务确实需要跨 crate 修改，说明 crate 划分有问题——先讨论边界，而不是硬做。

### 合并规则

- `feat/*` → `phase/*`：阶段内自测通过即可
- `phase/*` → `main`：**必须交付可运行的 `examples/` 验收 demo**（总纲规格 §15 硬性要求），且 CI 全绿
- 合并后立即删除已合并分支，遵循规格 §13「代码卫生」

## 提交信息格式

```
<type>: <描述>

<可选正文：为什么这么改，而非改了什么>
```

类型：`feat` `fix` `refactor` `docs` `test` `chore` `perf` `ci`

### 要求

- 描述用中文，**说清「为什么」而非复述 diff**——半年后回看时，diff 自己会说改了什么，只有你能说清为什么
- 一次提交只做一件事。混合提交会让 `git bisect` 失效
- **不添加任何 AI 署名**（全局 `~/.claude/settings.json` 已禁用 attribution）

### 示例

```
feat: 环面坐标类型与距离计算

大陆地图为真环面拓扑，两点距离需取四种绕法的最小值。
封装成类型而非散落的辅助函数，是为了让 CI 能静态检查
「禁止手写欧氏距离」这条约束（规格 §7.1）。
```

```
fix: 修正 mod 加载失败时连带中断后续 mod

原实现在解析清单阶段遇错即整体 return，导致一个损坏的 mod
会让其后所有 mod 都加载不了。改为逐 mod 隔离收集错误。
违反的是规格 §10.2 第 4 条「加载分阶段隔离」。
```

## CI 门禁

合并到 `main` 前必须全部通过（总纲规格 §14）：

- `cargo-deny` 许可证扫描
- 硬编码用户可见字符串检查
- 环面坐标手写欧氏距离检查
- 死代码检查
- 测试覆盖率 ≥ 80%
