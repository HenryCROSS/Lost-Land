# 0009 — 默认派生，只存偏差

**日期**：2026-08-17
**状态**：已生效的项目级原则，非单一模块的决定
**关键提交**：1c73265（钱包，修正棘轮问题）、3c2e3f7（名字生成）、22737d9（关系系统，标注「第三次复用」）、b222c4a（性格，标注「第五次复用」）
**影响范围**：`ll-world::entity`（钱包、性格）、`ll-world::naming`（名字）、`knowledge/design/society-and-affiliation.md`（关系系统）

## 背景

项目要支持数十万到数百万个 NPC，而这类规模下「给每个个体存一份完整数据」在多个子系统里都会撞上同一堵墙：钱包、姓名、人际关系、性格——任何一项如果按「每个实体一条完整记录」存，要么存储量爆炸（一百万 NPC 的姓名字符串就要几十兆），要么关系数据直接是 O(n²)（一百万 NPC 两两存关系是 10¹² 条记录，矮人要塞正是死在这类个体间两两检查上）。

灵感来源是 Valheim 的地形持久化模型：**能重算的不用存，被动过的才存**（`knowledge/design/agent-goals-and-economy.md:388`）。这个原则在本项目里被复用了多次。

## 原则

```
实际值(实体) = 默认派生值(实体, 上下文) + 个体偏移（仅在偏离基线时才存在）
```

默认派生值由种子、实体 ID、以及少量固定上下文（家族 ID、文化、距某个时间基准的时长）经确定性哈希计算得出，**零存储、用时现算**。只有真正偏离基线的个体——被玩家或剧情动过的那一小撮——才占用一条存储记录。

## 项目内的应用

| 应用 | 派生依据 | 偏移存什么 | 关键提交 |
|---|---|---|---|
| **钱包** | 公式(种子, entity_id, 距 `rebase_at` 的时长) | `wallet_delta` | 1c73265 |
| **姓名** | 名 = 音素表(hash(种子, entity_id))；姓 = 音素表(hash(种子, family_id)) | 无——名字从不偏离，纯函数恒定 | 3c2e3f7 |
| **人际关系** | 三层：组织↔组织稠密矩阵、个体→组织即 `Affiliation`、个体↔个体默认由前两层派生基线 | 每个 NPC 一个定容记忆槽（建议 8 格，LRU 淘汰） | 22737d9（标注「同一个思想的第三次复用」） |
| **性格** | `traits = f(hash(种子, npc_id), 文化的特质均值)` | 被剧情/玩家改变过的才存偏移 | b222c4a（标注「第五次复用」） |

（姓名严格说是这个思想的极端情形——它甚至不允许偏移，因为「同一个 NPC 永远同名」是设计要求本身，不是性能优化。）

### 关系系统的三层结构（复用中最复杂的一例）

| 层 | 规模 | 存法 |
|---|---|---|
| 组织 ↔ 组织 | 几十到几百 | 稠密矩阵，随便存 |
| 个体 → 组织 | 每人几条 | 就是 `Affiliation`，无新结构 |
| 个体 ↔ 个体 | 理论上 n² | 默认不存，由上两层派生基线 + 记忆偏移 |

派生基线按各类归属加权求和（同家族 +80、敌对势力 −60、异端 −40……），零存储；只有「你救过他的命」「你杀了他兄弟」这类才占一条记忆槽记录。两个白送的效果：关系天然不对称（`A→B` 与 `B→A` 各存各的，你恨他但他根本不认识你）；杀一个土匪全家恨你不需要存任何东西——只在自己对那个土匪的槽里记一笔仇，他兄弟的敌意是**算出来的**（兄弟与土匪同家族 +80 权重派生出敌意），一条记录波及整个家族。

## 适用条件

这个原则不是无条件适用的万能药，它要求同时满足：

1. **默认值可以从种子 + 少量固定 ID + 已知上下文确定性重算**，且计算成本是简单的整数公式（哈希 + 加权求和），不是搜索或模拟。
2. **绝大多数实体不偏离基线**——偏移必须是稀疏事件，否则退化成「每个实体都存一条记录」，派生带来的收益消失。
3. **偏移可以有界存储**（定容 + LRU 淘汰），否则长期游玩会让偏移记录无限增长，重新引入未受控的存储压力。

## 不适用的场合

**文化 ↔ 文化关系刻意做成静态而非动态**，不套用这个原则的「随时间演化」部分：文化隔阂不会因一场战争改变，它是世代尺度的东西；势力可以今天开战明天结盟，文化不行。把文化关系做成动态是设计文档明确指出的陷阱——这里的教训不是「这个原则不适用」，而是**「默认派生」不等于「必须允许偏移随意演化」**：势力/宗教关系是事件驱动的稠密矩阵（随事件更新），文化关系是几乎不变的静态亲和度（仅跨代缓慢漂移），两者都不走「个体记忆槽」这条路径，因为它们本来就是组织级别的量，不是「个体↔个体」层。

**已经升格为「被真正模拟」的厚层实体，不能再靠公式重算**——这是项目在 P2 阶段踩过的真实坑（「棘轮问题」）。

## 棘轮问题：一次真实的设计返工

最初的设计（P2 阶段设计文档）把「升格」写成单向操作：背景 NPC 一旦升格为被模拟对象就永久持久化，只有意外结束（死亡、逃脱）才可能降级。这是一个真实漏洞：玩上百小时后，被玩家碰过的 NPC 会累积成几千个全精度对象，廉价背景层不断萎缩，性能持续劣化且**不可逆**。

根因是把两件成本悬殊的事混成了一个开关。修正（1c73265）：**升格只永久授予「被记住」，「被模拟」仅在相关期间维持**。

- **被记住** = 存一个偏移量，成本极低，可以有几百万个。
- **被模拟** = 每回合跑决策，成本高，必须用 LRU 上限封顶同时活跃的数量。

只有轨迹真正偏离公式的 NPC（破产转土匪并离乡、被雇为随从、成为具名人物）才需要完整持久化——这类数量天然稀少，不构成棘轮。这次修正把「默认派生只存偏差」原则本身也拆细了一层：**「记住偏移」和「花算力模拟」是两件不同成本的事，只对后者设置上限，不能把两者绑在一起处理。**

## 代价

- 每一次复用都不是免费的抽象——每次都要重新设计「偏移存在哪、多大、怎么淘汰」，且需要重新验证在极端情况下（大量小偏移长期累积）不会产生不合理结果。姓名之外的三个应用（钱包、关系、性格）都各自定义了自己的偏移结构，彼此不共享代码。
- 派生基线的公式一旦定下就隐含了游戏平衡的很大一部分（例如「同职业 −10」与「同行会 +15」这类系数），调整这些系数会同时影响所有未被记录偏移的个体，牵动面比修改单条记录大得多。
- 这个原则依赖「大多数个体不偏离基线」的假设。若某个系统的设计导致大部分个体实际上都会偏离（例如某机制让绝大多数 NPC 都被玩家交互过），派生的性能收益会随偏移记录数量增长而消失，且届时很难判断问题出在原则本身还是具体系统设计。
