# 0008 — 行会中介贸易：把 O(n²) 约束做成世界观

**日期**：2026-08-17（设计定稿于 `knowledge/design/agent-goals-and-economy.md`，尚未实现，P3 计划未覆盖，属后续批次）
**状态**：已定稿的设计决定，等待实现
**关键提交**：b841f62（社会系统与智能体经济设计）
**影响范围**：`knowledge/design/agent-goals-and-economy.md` 第五、七节；未来的 `ll-sim` 经济模块

## 背景

设计参考对象之一是矮人要塞（Dwarf Fortress）：它的经济系统会在人口膨胀后死于「每个 NPC 逐个议价、逐个互相检查」这类个体间两两交互。本项目要支持数十万到数百万 NPC 的世界，任何 O(n²) 的个体交互都是不可接受的性能陷阱。

## 决定

**领地内的居民只与本地行会交易，居民之间不互市。跨领地贸易由行会之间派遣商队完成。**

```
居民 ←→ 本地行会 ←→ 商队 ←→ 其他领地的行会 ←→ 那里的居民
        （唯一的本地交易对手）    （唯一的跨领地通道）
```

玩家可以与行会交易，也可以在路上与商队交易——价格稳定但吃价差 vs 价格随机但可能更便宜，给了玩家真实的选择而非「到处都是同一个商店」。

## 为什么这样做：性能约束与世界观合二为一

| | 个体互市 | 枢纽辐射（行会中介） |
|---|---|---|
| 领地内交易配对 | N 个居民两两议价 → **O(N²)** | 每人对行会一次 → **O(N)** |
| 一万居民的量级 | 约 **5000 万次**配对 | **一万次** |
| 价格从哪来 | 从个体成交价涌现，难收敛 | 行会按属性定价，一个节点一个价 |
| 跨领地 | 每个商人各跑各的路线 | 行会间的稀疏路线网 |

设计文档明确指出这不是「为省算力编的设定」——中世纪的行会本来就垄断本地贸易、统一定价，省算力与真实性在这里同向。**架构约束与世界观设定合二为一**是这条决定被记录为 ADR 的原因：它把一个纯技术上的性能天花板，转译成了一条不需要额外解释的世界观规则。

## 行会定价

全整数、千分比：

```
本地价 = 基础价 × 库存系数（库存少则涨）× 需求系数（本地消费速率）
        × 行会政策（垄断度、保护主义）× 商路系数（进货成本，受商路安全影响）
```

行会买入价低于卖出价，价差是它的利润，也是它派商队、雇护卫、维持仓库的资金来源。

## 商队报价：分两档实现，先简后繁

一个自然的做法是让途中价格在起点价与终点价之间**按路程线性插值**——设计文档指出这「给出对的形状，但给错了理由」：它是几何决定的，不管路上发生了什么，商队走到半路就一定报中间价；而且经济上说反了——一支刚出发、货满仓的商队没有理由便宜卖，它愿意便宜卖的唯一理由是「拉过去还要花钱、还有风险」。

**第一档（MVP）——路程插值**：`行商报价 = lerp(出发时冻结的起点行会价, 目的地行会当前价, progress) + 风险挂钩的利润率`。起点价用出发时冻结的值（真实成本基础），目的地价用当前值（将要拿到的）——这个不对称是有意的。

**第二档（升级）——机会成本推导**：`商队最低卖价 = 目的地行会价 − 剩余运输成本 − 剩余风险损失期望`；`商队最高买价 = 起点行会价 + 已投入运输成本`。这会自然长出与插值相同的形状（刚出发时剩余成本高故底价低，快到时报价逼近目的地价），**但每个数字都有原因**，因此能对真实事件做出反应：

| 路上发生的事 | 纯插值 | 机会成本模型 |
|---|---|---|
| 前方商路出现土匪 | 无变化 | 风险溢价上升 → 报价变高 |
| 商队被劫、损失货物 | 无变化 | 需弥补损失 → 报价变高 |
| 快到终点仍未售罄 | 无变化 | 拉回更亏 → 甩货降价 |
| 该路段土匪被清剿 | 无变化 | 风险下降 → 报价变低 |

两档数据结构兼容，第二档是第一档的精修而非替代——只多算「剩余成本」与「剩余风险」两个量。运算量与插值相当（全整数，几次乘除）。

## 被否决的选项

**个体互市**（居民之间直接议价）——否决理由见上表：O(N²) 配对量在万人级世界已不可承受，且价格从个体成交价涌现难以收敛。

**商队报价用纯几何线性插值**（不分档，直接采用最终形态）——否决：给出正确的价格曲线形状，但对路上发生的事（土匪、清剿、被劫）完全没有反应，玩家的行动无法通过经济模型产生可见后果。设计选择先做插值再升级到机会成本模型，而不是一步到位，因为机会成本模型依赖土匪与商路安全度这些尚未实现的系统。

## 后果

- **负反馈环**：经济下行 → 居民破产 → 被行会除名（失去唯一合法交易渠道）→ 审计后转职土匪（不需要行会资格）→ 劫掠商队 → 商路不安全 → 行会加价、减少派遣商队 → 本地物资更紧张 → 更多人破产。这个循环同时解释了「为什么世界上有土匪」「为什么需要护卫」「为什么剿匪是有意义的玩法」，三者都不需要单独设计，是经济系统的自然结果。
- **决策必须事件驱动而非 tick 驱动**：行会自己决定下一次进货/定价/派遣的时刻并插入时间轴。枢纽模型让决策数量进一步下降——决策主体从「每个商人」变成「每个行会」，一百个领地就是一百个决策主体，而不是一万个。
- **代价**：这是一个已经写死在世界观里的架构假设。若后续设计想引入「玩家绕过行会直接找居民交易」之类的机制，需要重新评估性能影响，不能简单加一条例外——例外一旦存在就可能被 AI 驱动的经济系统大规模复用，重新引入 O(n²)。
- 商队第二档模型依赖的「路段安全度」目前是设计文档里的构想，尚未有实现落地；本 ADR 记录的是设计决定，不代表已完成实现验证。
