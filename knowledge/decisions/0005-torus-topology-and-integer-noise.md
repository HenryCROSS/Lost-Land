# 0005 — 环面世界拓扑与整数可平铺噪声

**日期**：2026-08-16 / 2026-08-17
**状态**：已生效
**关键提交**：2b12aad（环面坐标与距离）、5d0c1f8（整数可平铺噪声）、df5d11b（无缝地形生成）、c61ba5a（规格与实现对齐）
**影响范围**：`ll-core::torus`、`ll-world::noise`、`ll-world::generate`、规格 §7.1

## 背景

大陆世界地图设定为四边连通（环面拓扑）：向东走出边界从西侧回来，南北同理。这带来两个必须解决的问题：

1. 两点之间存在四条候选路径，「距离」与「最短方向」需要在这个拓扑下重新定义。
2. 地形噪声必须在接缝处无缝——玩家跨越世界边界不能看到地形突变。

而 [0002 — 世界状态一律用整数](0002-integer-only-world-state.md) 已经把「浮点不得进入世界状态」定成硬约束，这条约束延伸到地形生成：地形是世界状态的一部分，生成过程也不能用浮点。

## 决定：环面坐标

### 距离是 `TorusSize` 的方法，不是 `TorusPos` 的方法

`ll-core/src/torus.rs` 把 `delta`/`chebyshev`/`manhattan`/`squared_euclidean` 都定义在 `TorusSize` 上而非 `TorusPos` 上。理由：脱离世界尺寸，两个环面坐标之间的距离根本无法定义。这个 API 形状让「忘记传尺寸」变成**编译错误**，而不是运行时的错误答案。

`TorusPos` 字段私有，只能经 `TorusSize::wrap`（`torus.rs:123`）构造，以保证「坐标恒被规范化到 `[0, width) × [0, height)`」这条不变式无法从外部破坏。内部用 `rem_euclid` 而非 `%`：Rust 的 `%` 对负数返回负余数（`-3 % 10` 得 `-3` 而非 `7`），会直接破坏不变式。

### `delta` 返回最短带符号偏移，接缝由此被构造性吸收

`TorusSize::delta`（`torus.rs:137`）返回从 `from` 到 `to` 的最短带符号位移，内部 `shortest_offset`（`torus.rs:145`）先取正向偏移对周期取模，正向距离超过半周则改用反向。**位移恰为半周时固定取正方向**（`forward * 2 > extent` 用 `>` 而非 `>=`）——这不是随手选的分支方向，而是必须有的稳定打破平局规则：否则同一局面在不同调用间可能返回不同结果，破坏确定性重放。

这个设计的直接后果是：跨接缝绘制**不需要额外处理**。规格原文曾写「精灵批处理需支持最多 4 份偏移副本」，实际 P1 实现从未画过副本——`TorusSize::delta` 返回的已是最短位移，绕接缝的情形被位移计算本身吸收了（c61ba5a 订正此处文档，见下节「被否决的选项」）。

### 只提供距离的平方，不开方

`squared_euclidean`（`torus.rs:174`）刻意只返回平方值。开方必然引入浮点，而比较远近时平方值与原值单调等价，绝大多数场景不需要真实距离。

## 决定：整数可平铺噪声

### 不用 `noise` crate

`crates/ll-world/src/noise.rs:1-24` 记录了一次实测评估，先澄清了一个容易想当然的误区：**并非所有浮点运算都跨平台不确定**。IEEE 754 规定 `+ - * / sqrt` 必须逐位精确，真正不确定的是 `sin`/`cos`/`exp`/`pow` 这类超越函数——IEEE 754 不规定其精度，不同 libm 实现结果不同。查过 `noise` 0.9.0 源码：Perlin/Simplex/Value 的核心实现不含超越函数，所以它的确定性本身不是真正问题。

不采用它的三条真实理由：

1. **它的 seamless 是「四角混合」而非真无缝**——源码取 sw/se/nw/ne 四个采样值混合，边缘能对上但中间会糊化，与环面拓扑需要的构造性无缝不同。
2. **它是整图构建器而非逐坐标采样器**——`PlaneMapBuilder` 一次生成整张图，而本项目分块惰性生成（玩家走到哪生成哪），用它就得开局把整个世界算完，与 LOD 和惰性追赶的设计直接冲突。
3. **输出是 `f64`，仍需量化成整数**，多一道转换与一处边界舍入的坑。

### 用模格点而非 4D 投影

让噪声在环面上无缝的常见做法，是把 2D 环面嵌入 4D 空间再采样 4D 噪声——**那条路需要 `sin`/`cos`，正是上面说的超越函数，反而会真正引入跨平台不确定性**。

模格点方案不需要绕：格点索引对周期取模即可（`lattice_x mod period_x` 使 `x = 0` 与 `x = period_x * CELL_SIZE` 命中同一格点）。**无缝是构造上保证的，不是近似出来的**，且全程整数。代价：世界宽高必须是 `period * CELL_SIZE`，由 `generate` 模块在入口校验——与其让缺陷以视觉异常的形式出现在运行时，不如在生成入口直接拒绝。

其他细节决定（5d0c1f8）：

- 插值用**五次多项式**而非线性——线性插值会在格点处留下可见的方格棱线。
- 中间计算用 `i64` 承接以免立方溢出。
- 格点索引打包成 `u64` 时用**移位**而非相加，否则 `(3,5)` 与 `(5,3)` 会撞进同一个值，地形上出现对角线状伪影。
- 多倍频的频率翻倍用 `checked` 乘法：层数多时坐标会溢出，溢出后的采样点是错的却不会报错。

## 实测数据：接缝无缝性

用 `generate_terrain` 实跑 512×320（P2 收尾控制者独立核验）：

| 位置 | 相邻格地形变化率 |
|---|---|
| 东西接缝 | 15.9% |
| 南北接缝 | 9.8% |
| 世界内部 | 24.4% |

**接缝比世界内部还平缓**，统计上就是个普通位置。四角一致（全为深水），地形分布与早期探针「复刻阈值表自行判定」的结果逐位相同，实现与计划的阈值表无偏差。

无缝性单独立了「接缝两侧地形一致」的测试，而不是依赖噪声层的无缝性属性测试：噪声无缝不等于地形无缝，阈值判断本身也可能引入不连续（df5d11b）。这条属性测试后来（e7e0f6f）发现只覆盖了 `sample()` 而生产代码实际走 `octaves()`，补齐后用「故意改错取模再改回」的方式验证了测试本身有效——错误注入后两条新测试立刻转红，且能自动收缩出最小复现。

## 被否决的选项

1. **`noise` crate**——三条理由见上节。
2. **4D 投影嵌入采样 4D 单纯形噪声（规格原文案）**——需要 `sin`/`cos`，会真正引入跨平台不确定性；c61ba5a 已更正规格 §7.1 措辞，并记录了改的原因，而不是直接覆盖，避免后来者重新提出被否决过的方案。
3. **精灵批处理画最多 4 份偏移副本处理跨接缝（规格原文案）**——被 `TorusSize::delta` 的最短位移直接吸收；多副本方案既慢又容易出边界错误。这一条规格与实现的偏离持续了整整一个阶段无人发现，因为评审只问「实现是否满足规格」，不问「规格是否已经过时」——这次订正直接催生了「每个阶段收尾必须反向核对一次规格」的项目纪律。

## 后果

- 世界尺寸背上两条硬约束：任一维度必须大于视口跨度（43×25 格），且宽高必须是 `CELL_SIZE`（16）的整数倍，否则接缝不连续或产出重复坐标。两处约束分别由 `ChunkGrid::new` 与 `generate_terrain` 在构造点/入口拒绝。这是长期存在的接口负担，后续阶段新建世界尺寸时必须记得。
- 环面拓扑仅适用于大陆世界地图层；进入具体区域后的分区场景是有界局部地图，不做环绕——这条边界写在 `torus.rs` 模块文档里，避免被误用到不该用的场景。
- 「手写欧氏距离」这类缺陷极难定位（小地图上明明相邻、寻路却绕了半个世界，出错处看起来完全正常），因此自 P1 起由 CI 静态检查强制禁止手写距离，在此之前只能靠人工评审把关。
