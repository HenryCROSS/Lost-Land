# 装备栏位与占位掩码

**落地状态**：纯设计。`crates/` 中尚未找到 `SlotMask` 或本文档定义的任何槽位类型（已核实：全代码库检索无匹配）。

## 一条规则覆盖所有特例

双手剑、全身板甲、连体服、独眼罩——这些看起来是四种特殊情况，实际是**同一个机制**：每件装备声明自己**占用哪些槽位**，装备时凡与之相交的已装备物品全部自动卸下。这里的 `SlotMask` 就是[物品系统](item-system.md) `ItemDef.equip_mask` 字段的类型。

```rust
/// 装备占用的槽位集合，按位表示。
///
/// 22 个槽位恰好塞进 u32，交集判定就是一次按位与——这是把「双手武器」
/// 「全身甲」「连体装」统一成一条规则的关键。若为每种情况写特例，
/// 每新增一类装备形态都要改一次装备逻辑。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct SlotMask(u32);

impl SlotMask {
    /// 两个掩码是否有交集。装备时用它找出需要卸下的物品。
    pub const fn intersects(self, other: SlotMask) -> bool {
        self.0 & other.0 != 0
    }
}
```

举例：

```
双手剑     = MAIN_HAND | OFF_HAND
全身板甲   = BODY | SHOULDER_L | SHOULDER_R | ARM_L | ARM_R | TASSET | LEGS
连体服     = BODY | LEGS
独眼罩     = EYES              （只占眼部，脸部仍可戴面具）
```

## 左右分离的设计价值

左右肩甲、左右臂、左右手甲、左右靴、左右戒指全部独立，这不只是细致：

- **可以捡到不成对的装备**。两只靴子属性不同是很好的随机性来源，也让「凑齐一套」有了意义。
- **部位受创**可以定向——断了左臂就卸掉左臂装备。
- **视觉辨识度**：左右不对称的角色比完全对称的更好认。

代价是美术资产量翻倍。缓解办法：图集元数据加一个「可镜像」标记，可镜像的装备只画一版、渲染时水平翻转；只有刻意不对称的装备才画两套。

部位受创定向卸装，与[属性系统](attribute-system.md)的护甲计算共用同一份槽位布局——护甲是按已装备物品逐槽聚合出来的，卸掉一个槽位就少一份护甲来源。

## 渲染层

「层」只决定**精灵绘制顺序**，不构成装备约束——内层不必先装备，外层也不要求内层存在。

把层做成硬约束（如「穿外套必须先穿内衣」）是常见的过度设计：它挡不住任何真实问题，却会在玩家快速换装时制造一连串烦人的报错。

层序从内到外：`内 → 中 → 外`。同层内按槽位号排序，保证确定性。

## 装备流程

装备一件物品是一个 `Effect` 序列，不是一次原地修改：

```
Intent::Equip { actor, stack }
    ↓ resolve（纯函数，只读世界）
Vec<Effect> = [
    Effect::Unequip { actor, slot: 与掩码相交的每一个已装备槽位 },
    Effect::MoveItem { 被卸下的物品 → 背包，背包满则 → 地面 },
    Effect::Equip { actor, stack, mask },
]
    ↓ apply（唯一写入口）
```

**背包满时卸下的装备掉到地上而不是消失。** 装备凭空消失是最招玩家恨的机制之一。这与[物品系统](item-system.md)「拿起、丢下、交易、装备…全部走同一个 `Effect::MoveItem`」是同一条纪律的两处体现。
