## 一、核心：势力 / 宗教 / 行会 / 文化 是同一个结构

它们看起来是四个系统，实际只有一个数据结构、四种用途：

```rust
/// 一个实体对某个组织的归属与声望。
///
/// 势力、宗教、行会、文化用同一个结构，是因为它们对游戏逻辑提出的问题
/// 完全相同：「这个实体属于谁」「关系好到什么程度」。分成四套并行结构，
/// 就要写四遍偷窃判定、四遍交易折扣、四遍行为树条件。
#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct Affiliation {
    /// 归属类别。
    pub kind: AffiliationKind,
    /// 具体组织，指向注册表。
    pub org: ContentIndex,
    /// 声望，千分比。负值表示敌对。
    pub standing: i32,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub enum AffiliationKind {
    /// 势力：领土、法律、税收、兵役。
    Faction,
    /// 宗教：戒律、神祝、什一税。
    Religion,
    /// 行会：技艺、订单、垄断、会费。
    Guild,
    /// 文化：与生俱来，不索取任何东西，只塑造偏好。
    Culture,
    /// 家族：血缘与姻亲。与生俱来，可因联姻扩展。
    Family,
    /// 职业：你实际在干什么。`standing` 在此表示**熟练度 / 资历**。
    Profession,
}
```

一个实体持有 `Vec<Affiliation>`。**四类可以并存且互相冲突**——一个信奉海神的矮人铁匠工会成员，可能同时是山地王国的臣民，而海神教与山地王国正在交战。**这种张力是内容的来源，不是要消除的问题。**

### 各类提供什么、索取什么

| 类别 | 提供 | 索取 | 脱离方式 |
|---|---|---|---|
| **势力** | 领土通行、卫兵保护、法律仲裁 | 税收、兵役、忠诚 | 迁徙、叛逃（声望暴跌） |
| **宗教** | 士气、神祝能力、丧葬、庇护 | 什一税、遵守戒律、朝圣 | 改宗（原教声望暴跌） |
| **行会** | 技艺传授、订单渠道、垄断价 | 会费、质量标准、不得外传 | 退会、被逐 |
| **文化** | 偏好、建筑风格、命名、节庆 | **不索取**——文化是天生的 | 几乎不可改（除非幼年迁徙） |

**文化不索取任何东西，这是它与其余三者的根本区别。** 势力/宗教/行会是**加入**的，文化是**长成**的。

### 这个统一带来的直接回报

同一个 `Affiliation` 查询同时驱动：

- **偷窃判定**——物品的 `Owner::Faction(id)` 与拿取者的势力归属比对（见 [物品系统](item-system.md)）
- **交易价格**——同势力/同行会打折，敌对加价或拒绝交易；行会定价公式本身见[Agent 目标与经济](agent-goals-and-economy.md)「行会如何定价」，该公式在公示的「本地价」之外单独乘一项「买家归属系数」实现这条折扣（原冲突清单条目 2，已裁定）
- **任务接取权**——行会任务只对会员开放，神殿任务看虔诚度，任务本身的结构见[Agent 目标与经济](agent-goals-and-economy.md)
- **行为树条件**——`(has-affiliation? 'religion 'sea-god)` 直接可查
- **战争与结盟**——势力之间的 `standing` 就是外交关系

## 二、文化是一组权重，不是一个标签

这是「文化聚落」能真正长得不一样的关键。文化定义的**不是外观描述，而是生成时的权重**：

```rust
/// 文化定义。由注册表提供，mod 可自由新增。
pub struct CultureDef {
    pub id: NamespacedId,
    pub name_key: String,

    /// 建筑材料偏好，千分比权重。
    pub building_materials: Vec<(ContentIndex, i32)>,
    /// 选址地形偏好，千分比权重。
    pub site_terrain: Vec<(TerrainKind, i32)>,
    /// 经济结构偏好：农耕 / 游牧 / 商贸 / 采矿 / 渔猎。
    pub economy_weights: Vec<(EconomyKind, i32)>,
    /// 命名用的音节表与拼接规则。
    pub naming: NamingRules,
    /// 社会结构：家族 / 氏族 / 城邦 / 部落。
    pub social_structure: SocialStructure,
    /// 主流宗教倾向，千分比。
    pub religion_affinity: Vec<(ContentIndex, i32)>,
}
```

**同一套聚落生成器，喂不同的文化权重，产出完全不同的城镇。** 不需要为每种文明各写一个生成器——这与「本体即 Mod」是同一个思路：mod 加一份 `CultureDef` 就能加一种文明。

三种文化在同一片地形上的选址结果：

| 文化 | 选址权重 | 结果 |
|---|---|---|
| 海洋民 | 沿海 900、平原 200 | 沿海岸线串珠状分布 |
| 山地族 | 丘 700、山 600、森林 300 | 聚于内陆高地，彼此隔绝 |
| 草原游牧 | 草原 900、丘 400 | 分散、规模小、位置随季节变 |

## 三、地图结构层

在环面大陆的地形之上叠一层**结构层**。结构生成在地形之后，且**依赖地形**——不会把城建在深水里。

```rust
pub enum StructureKind {
    /// 聚落：村 / 镇 / 城，规模由人口决定。
    Settlement,
    /// 道路：连接聚落，降低移动代价。
    Road,
    /// 遗迹：可探索，有战利品与危险。
    Ruin,
    /// 地标：导航参照，无功能但有辨识度。
    Landmark,
    /// 资源点：矿脉、林场、渔场——经济的源头。
    ResourceNode,
}
```

### 道路是经济的骨架，不是装饰

道路降低 `move_cost`，因此**商队会沿路走**，因此**沿路的聚落更繁荣**，因此**繁荣的聚落又会修更多路**。

这个正反馈是城市自然分化出大小的机制，**不需要手工指定哪座城是首都**。

道路生成用聚落间的最小生成树 + 按贸易量加权的额外连边。**必须走环面最短路径**（`TorusSize::delta`），否则会出现绕半个世界的路。

### 资源点决定聚落的经济性格

聚落的经济结构 = **文化偏好 × 周边资源点**。海边的农耕文化会变成渔村，山里的商贸文化会变成矿业中转站。**性格是涌现的，不是指定的。**

## 四、宗教如何真正参与世界运转

### 戒律驱动行为

每个宗教有一组 `Tenet`（戒律），信徒违反会掉声望：

- 「不得食用兽肉」——影响 NPC 采购与市场需求
- 「日落后不得交易」——影响商店营业时间
- 「须以石建屋」——影响建筑材料选择
- 「不得与异教徒同席」——影响社交与任务接取

**戒律不是文本描述，是行为树能查询的条件。** 通过 Steel 脚本定义，与技能效果走同一套注册通道。

### 神殿是经济节点

神殿同时是：**什一税的收取点**（资金汇入）、**任务发布点**（用信众捐款悬赏）、**庇护所**（受伤或被通缉者的去处）、**神祝的来源**（消耗信仰值换增益）。

它有自己的钱包，因此**能像任何 agent 一样发布任务**——修缮神殿、护送朝圣者、讨伐异端。

### 宗教关系独立于政治边界

宗教的 `standing` 矩阵与势力的**分开维护**。这是这一层最有意思的张力来源：两个交战国的信徒可能同属一教，而同一国内的两教可能水火不容。

**这正是「宗教即势力」那个更省事的方案会丢掉的东西。** 矮人要塞验证了这条可行：它的信仰按「宗教团体」记录而非按政治文明记录，所以一个地精加入某宗教团体后，即便该宗教主要由别的文明信奉，他依然可以信那个神。

### 信仰强度是廉价标量

与钱包、名字同类：**神祇 ID + 虔诚度**。背景 NPC 按所属聚落的主流信仰 + 确定性随机生成，零额外开销。DF 用五档（狂热 / 虔诚 / 无标签 / 随性 / 半信半疑），可直接借鉴。

### 传播机制全部复用已有系统

| 宗教机制 | 复用什么 |
|---|---|
| 先知 | 具名 NPC，与领主、大商人同类，不是新概念 |
| 信徒转化 | **职业流动那套批量结算**，只是流动的字段从「职业」换成「宗教归属」 |
| 庙宇 | 结构 footprint 预留机制，信徒数过阈值就在骨架层占一块地 |
| 朝圣 | 商队的 progress 插值状态机，沿已有道路走一趟 |
| 宗教冲突 / 圣战 | 外交 + 战争系统，触发阈值换成宗教声望 |

**没有一条需要新写系统。**

### 必须避开的一个坑：新宗教要能在游玩中诞生

DF 的先知**只在世界生成的历史模拟阶段被创造**，进入游戏后没有再生成先知的机制——结果是实际游玩中新宗教基本无法自然产生。

这与本项目「经济、外交都要在游玩过程中持续演化」的哲学直接冲突。**不要照抄这一点**：把「先知诞生」设计成后台模拟层里一个**持续存在的低概率事件**——任何虔诚度极高的具名 NPC，每次结算都有极小概率「顿悟」成为新先知、拉出一个分支教派。

这是 DF 踩过的坑，可以直接绕开。

## 四之二、家族与代际

家族是 `AffiliationKind` 的第五个变体，**不需要新系统**。这一下白送了一批能力：

| 已有机制 | 家族接上后自动获得 |
|---|---|
| 声望 `standing` | **得罪一个成员，整个家族对你降好感** |
| [物品归属](item-system.md) `Owner::Faction` | 家族共有财产、祖传装备 |
| 交易折扣 | 亲戚给你打折 |
| 行为树条件 | `(has-affiliation? 'family 'X)` → 复仇、庇护、偏袒 |
| 任务接取权 | 家族内部委托 |

### 血缘记录是极轻的

除 `Affiliation` 之外，另存一份最小的血缘结构：

```rust
pub struct Kinship {
    pub father: Option<EntityId>,
    pub mother: Option<EntityId>,
    pub spouse: Option<EntityId>,
    pub children: Vec<EntityId>,
}
```

**每个 NPC 只存几个 ID，度数有界，不会重新引入 O(n²)。** 「谁是 X 的子女」是 O(1) 查询；「X 与 Y 是否有血缘」这类需要遍历的查询应当限制深度（建议 3 代以内），避免退化成图遍历。

### 真正的价值在代际

家族与已定系统咬合得很紧：

- **继承**——NPC 死亡时钱包、房产、归属、恩怨传给继承人。**财富跨代累积，自然长出世家与阶层分化**，不需要指定「谁是贵族」
- **职业世袭**——行会名额传给子女，「铁匠世家」自然出现，也解释了职业为何在家族里聚集
- **血仇**——杀了土匪，其兄弟所属家族对你的声望归零。**不需要写「复仇系统」**，这是家族声望 + 已有行为树的组合结果
- **人口更替**——NPC 会老、会死、被子女替代。这是**群体过程**，在 cohort 层批量计算，成本与人口线性

### 命名与家族

名字是纯函数（`name(seed, npc_id)`，按文化音素表生成），**家族姓氏同理**——由家族 ID 派生，子女自动继承。DF 用几万个矮人验证过：起名字本身极便宜，与性能瓶颈无关。

## 四之三、关系系统：默认派生，只存偏差

**这是整套设计里最容易掉进 O(n²) 的地方。** 一百万 NPC 两两存关系是 10¹² 条记录，绝无可能；而矮人要塞正是死在个体间的两两检查上。

解法与钱包、与 Valheim 的地形是**同一个思想的第三次复用**：**默认派生，只存偏差。**

### 三层结构

| 层 | 规模 | 存法 |
|---|---|---|
| **组织 ↔ 组织** | 几十到几百 | **稠密矩阵**——100 个势力也才 1 万条，随便存 |
| **个体 → 组织** | 每人几条 | 就是 `Affiliation`，无新结构 |
| **个体 ↔ 个体** | 理论上 n² | **默认不存，由上两层派生** |

### 派生基线

两个素不相识的 NPC 之间的关系完全可以算出来：

```
派生基线(A, B) = Σ 各类归属的贡献

    同家族      +80
    同势力      +20        敌对势力    −60
    同宗教      +25        异端        −40
    同行会      +15
    同文化      +10        异文化       −5
```

**零存储，用时现算。** 一百万 NPC 之间的一万亿对关系，一条都不用存。

### 只存偏离基线的部分

```
实际关系(A → B) = 派生基线(A, B) + 个体记忆偏移
```

「你救过他的命」「你杀了他兄弟」「你跟他交易过五十次」——这些才占一条记录。

**每个 NPC 一个定容记忆槽**（建议 8 格，LRU 淘汰），家族成员与剧情钉住的对象占永久位。**规模因此有界，不随交互次数无限增长**——与「棘轮问题」用的是同一道闸。

### 两个白送的效果

**① 关系天然不对称。** `A→B` 与 `B→A` 各存各的。你恨他但他根本不认识你——这更真实，也是很好的戏剧素材。

**② 杀一个土匪，他全家恨你——不用存任何东西。**

你只需在自己对「那个土匪」的记忆槽里记一笔仇。他兄弟对你的态度是**算出来的**：兄弟与土匪同家族（+80 权重），而你与土匪结了仇 → 派生出敌意。**一条记录，波及整个家族。**

### 职业也参与关系派生

`AffiliationKind::Profession` 的 `standing` 表示**熟练度 / 资历**。这一个字段同时解决三件事：

| | 靠什么 |
|---|---|
| 产品质量与收入 | 熟练度直接进批量公式 |
| **转行摩擦** | 熟练度即**沉没成本**——干了二十年的铁匠不会因一季度收益差就改行。这正是[「受限转行」](agent-goals-and-economy.md)需要的阻尼器，不必再单列「转行成本」字段；该文档的职业审计判定条件列表已把熟练度补为收益差距阈值的调制项（原冲突清单条目 3，已裁定） |
| 师徒关系 | 高熟练度可教低熟练度，「有人能教」这个转行前提直接可查 |

**副职天然支持**：`Vec<Affiliation>` 里可以有多条 `Profession`，各有各的熟练度。「当前职业」= 标记为主职的那一条。规格 §15 的 P5 本就列了副职，现在它不需要新机制。

职业间的关系喂进派生基线：

```
同职业      −10    ← 同行是冤家（竞争）
互补职业    +15    ← 矿工 ↔ 铁匠（供需互利）
对立职业    −50    ← 卫兵 ↔ 土匪
```

> **「同职业 −10」与「同行会 +15」方向相反，这不是矛盾，是两个不同的轴**：职业是你实际在干什么（同行竞争），行会是你选择加入的组织（同门相护）。
>
> 于是「同行会的两个铁匠」净值 +5（相护压过竞争），而「行会内铁匠 vs 行会外野铁匠」是 −10（纯竞争，无相护抵消）。**行会为什么排他、为什么值得交会费，从这里自然长出来，不用另编理由。**

**薄层只存主职**：`profession` 与 `proficiency` 两列定宽。副职只属于厚层——背景农夫就一个职业，这既符合性能纪律也符合现实。薄层升格时，主职两列转换成一条 `Profession` 归属。

#### 职业声望是局部的，不是全局常量

**裁定（原冲突清单条目 4，已裁定）**：这里的「职业声望」是聚落 × 职业维度的社会评价，与[属性系统](attribute-system.md)次级属性表里个人的「**名望**」（原文档曾用「威望」，与「声望」同词根，现已改名以消除撞车）是两个不同的量——一个挂在职业与地点上，来自当地文化与经济；一个挂在角色本人身上，来自个人事迹。二者是否叠加、如何共同决定玩家实际感受到的「别人怎么看我」，仍留给后续数值设计回答，但这已经不是一处文档冲突：两个量现在有各自不会撞车的名字，读者不会再把它们误认成同一个东西。

**同一个人换个地方，待遇就不一样。**

```
本地职业声望(职业, 聚落) = 文化基准 × 经济状态修正 × 本地条件修正
```

| 输入 | 作用 | 例 |
|---|---|---|
| **文化基准** | 每个 `CultureDef` 带一张职业声望表 | 商贸文化敬重商人；尚武文化视商人为逐利小人 |
| **经济状态** | **稀缺抬高该职业的地位** | 饥荒时农夫金贵，丰年时农夫平平 |
| **本地条件** | 周边资源决定谁不可或缺 | 矿镇里矿工受尊敬；港口城里矿工只是下等劳力 |

**计算量微不足道**：一百个聚落 × 几十种职业 = 几千条，每次经济结算批量刷新一次即可。

声望差喂进派生基线，且**天然不对称**——正好契合关系系统的不对称设计：

```
贵族 → 皮匠：轻蔑（−30）
皮匠 → 贵族：畏惧或怨恨（取决于性格的记仇与忠诚）
```

##### 五个白送的玩法后果

1. **同一角色换地方待遇不同**——玩家在矿镇是座上宾，到港口城成了粗人，不需要写任何剧本
2. **转职有社会代价**——在鄙视皮匠的文化里当皮匠，收入可能不错但没人愿与你打交道。这给「受限转行」加了经济之外的一层摩擦
3. **移民有了动机**——农业镇里的矿工想搬去矿镇，那里他值钱。人口流动自然发生
4. **阶层固化自然涌现**——低声望职业 + 行会名额世袭 + 家族继承，**不需要设计种姓制度，它自己会长出来**
5. **土匪不只是经济底层，也是社会底层**——这让「破产 → 土匪」的负反馈环更难回头：光有钱还不够，还得有人肯跟你交易

##### 一个必须正视的警告

**这条设计会自动产生令人不适的社会结构**——固化的阶层、被鄙视的群体、世代难以翻身的家族。这正是它有力量的地方（矮人要塞的悲剧感即源于此），**但它是涌现的、不是逐条写出来的**，因此无法预先审查每一个结果。

若不想要某类结果，必须在**机制层面**预留出口，而且**要现在就想，不能等它长出来再补**：

- 让**高熟练度压过低声望**——技艺精湛的皮匠受人尊敬
- 让**财富部分抵消出身**——富商可以买到体面
- 让**特定事件重置声望**——救过全城的人不再被问出身

### 性格：不是归属，但参与关系

**性格刻意不做成 `AffiliationKind`。** `Affiliation` 是离散的成员身份 + 声望，而性格是**连续的特质向量**——你不「加入」内向，也不存在「内向阵营与外向阵营的外交关系」。

更要紧的是：**塞进归属桶会丢掉连续性**，而连续性正是它最有用的地方——「保守者转行阈值更高」「商队风险偏好」都需要可比较的数值，不是标签。

```rust
/// 性格特质。定宽整数数组，千分比，范围 [-1000, 1000]。
///
/// 六个 i16 共 12 字节，一百万 NPC 才 12 MB，且定宽——完美适配薄层的
/// 列式存储。
pub struct Traits {
    pub courage: i16,        // 勇敢 ↔ 怯懦
    pub greed: i16,          // 贪婪 ↔ 慷慨
    pub loyalty: i16,        // 忠诚 ↔ 善变
    pub sociability: i16,    // 合群 ↔ 孤僻
    pub vindictiveness: i16, // 记仇 ↔ 宽容
    pub piety: i16,          // 虔诚 ↔ 世俗
}
```

它以**两条路径**参与关系系统：

**① 相容度贡献派生基线**——按特质距离算，几次整数运算，**不存任何两两数据**。

**② 调制关系的变化速率**——同一件事，不同性格反应不同：

- **记仇者**：记忆偏移衰减慢，仇能记一辈子
- **宽容者**：衰减快，恩怨很快就淡
- **合群者**：记忆槽更大，认识更多人
- **孤僻者**：槽少，只记得几个人

**「记仇」不是描述性的形容词，而是直接改变衰减速率的参数。**

### 每个特质都接着一个已有机制

| 特质 | 接口 |
|---|---|
| 勇敢 | 商队 `risk_tolerance`、是否逃跑、破产后**是否敢当土匪** |
| 贪婪 | 议价、悬赏定价、**是否偷窃** |
| 忠诚 | **转行阈值**（受限转行的阻尼器）、叛离势力、随从背叛 |
| 合群 | 关系基线偏移、**记忆槽容量** |
| 记仇 | **记忆衰减速率** |
| 虔诚 | 戒律遵守度、什一税、**是否可能顿悟成先知** |

**没有一个特质是纯装饰的。** 加特质前必须先回答：它接在哪个已有机制上？答不上就不要加。

### 背景 NPC 的性格不用存

```
traits = f(hash(种子, npc_id), 文化的特质均值)
```

文化提供均值（山地族更倔强、商贸文化更贪婪），个体在均值附近波动。**零存储、可重算、同一 NPC 永远同性格**——只有被剧情或玩家改变过的才存偏移。

**这是「默认派生，只存偏差」在本设计里的第五次复用。**

### 势力关系与文化关系不是一回事

| | 变化方式 | 存法 |
|---|---|---|
| **势力 ↔ 势力** | **事件驱动**：开战、媾和、通商、背叛 | 稠密矩阵，随事件更新 |
| **宗教 ↔ 宗教** | 事件驱动，但比势力慢 | 稠密矩阵 |
| **文化 ↔ 文化** | **几乎不变**——它是「彼此觉得多陌生」 | 注册表里的**静态亲和度**，仅跨代缓慢漂移 |

**把文化关系做成动态的是个陷阱**：文化隔阂不会因为一场战争而改变，它是**世代尺度**的东西。势力可以今天开战明天结盟，文化不行。

### 记忆衰减

个体记忆偏移应当**随时间衰减**（仇恨会淡、恩情会忘），这是薄层上的一次批量运算，成本与记忆槽总数线性——而槽数因定容而有界。

**永久记忆**（血仇、救命之恩）可标记为不衰减，数量由内容设计控制。

## 六、LOD 兼容性（不可协商）：轴是「是否被模拟」，不是距离

**裁定（原冲突清单条目 1，已裁定）**：统一术语为**背景层 / 前景层 / 具名层**——这是本项目对 NPC 精度分层的唯一说法。早期决策 21 里「近景 / 中景 / 远景」的距离式提法作废，理由见下。

### 距离不是那条轴

「近景/中景/远景」把精度和空间距离绑死，会推出一个错误结论：一个具名 NPC 走到地图另一头，就该像背景 NPC 一样休眠、丢掉细节。但**名字、家族、恩怨这些「被记住」的东西不会因为走远了就消失**——一个流落天涯的显赫家族继承人，依然是那个继承人，族谱与历史事件依然认得他。

真正决定成本的轴是升格棘轮问题（见[Agent 目标与经济](agent-goals-and-economy.md)「棘轮问题」一节）确立的两分：

| | 成本 | 边界 |
|---|---|---|
| **被记住**（有持久状态：名字、钱包偏移、家族、恩怨记忆） | 便宜 | 永久，无上限 |
| **被模拟**（每回合跑真实决策） | 昂贵 | 有界，LRU 淘汰 |

「距离」在这两条轴上都不是决定因素——它只是「玩家附近」这个信号的一个近似，用来估计谁**当前**该被模拟，不决定谁该被记住。

### 三档精度与两条轴的关系

势力、宗教、行会的运作**必须能在 cohort 层批量进行**：

| 档 | 被记住 | 被模拟 | 归属如何运作 |
|---|---|---|---|
| **背景层** | 是——批量公式 + 可选的钱包/关系偏移量 | 否 | 按「同聚落 + 同归属」聚合，声望变动批量应用；组织级状态用闭式公式跳算 |
| **前景层** | 是 | 是——数量天然被玩家视野限制，规模有界 | 个体 agent 各自持有 `Affiliation`，个体决策 |
| **具名层** | **是，永久，不因距离而丢失** | **视情况而定，与前景层同受「被模拟」的 LRU 上限约束，不因「具名」这个身份本身而豁免** | 名字/家族/历史地位永久保留；是否跑真实决策取决于当前是否在被模拟集合里 |

**「具名」属于被记住这条轴，「前景」属于被模拟这条轴，两者正交**——一个 NPC 可以被记住但不被模拟（远走他乡、暂不跑决策的具名角色），这正是当初解决升格棘轮问题的关键：升格只永久授予「被记住」，「被模拟」仅在相关期间维持。把这两条轴压扁成一条「距离」轴，就会得出「他远了所以该休眠」这种对具名 NPC 不成立的结论——这正是本节此前的矛盾根源。

**关键**：组织级状态变化必须能用**闭式公式跳算**。声望自然衰减、税收累积、人口增减都要能一次性算完一整段时间，不能靠循环补跑——否则玩家离开三年再回来时会卡死。

[Agent 目标与经济](agent-goals-and-economy.md)「背景层 / 前景层 / 具名层」一节用的正是同一套术语与同一条两轴关系，两份文档现已对齐。

### 五、四节「宗教」：只有载体失效，结论全部成立

本节其余论证——戒律是可查询条件、神殿是经济节点、宗教关系独立于政治边界、信仰强度是廉价标量、
传播机制全部复用已有系统、新宗教必须能在游玩中诞生——**一条都不需要改写**。

### 八、下一批要用这份文档时，先看这三处

### 1. `AffiliationKind` 现在是**五个**变体，不是六个——`Profession` 已删除

上一节一、1 写着「六个 `AffiliationKind` 变体一字未改」，一节正文与
[总索引](README.md) 也都写着「势力/宗教/行会/文化/家族/**职业**六类共用一个数据结构」。**今天是五个**：

```text
Faction   Religion   Guild   Culture   Family
```

`crates/ll-world/src/entity/affiliation.rs` 模块文档记录了删除过程与一处**裁定无法字面照办**的情况：项目所有者的裁定是「`Profession` 改名为 `Guild`」，理由是「一个铁匠可以不加入铁匠行会——从属关系表达的是行会成员身份」；但 `Guild` **本来就已经存在**（自 P3 起六个变体里的第三个，一字未改），改名会撞出两个同名变体。**按裁定的意图，正确动作是删掉 `Profession`**——所有者要的那件事已经由现成的 `Guild` 表达了。

删除**不是一次存档迁移**：`Profession` 从未被构造过。

**顺带解决了一个挂了四轮没等到裁定的问题**：`Agent.profession` 与 `AffiliationKind::Profession` 在描述同一件事、要不要合并——今天的答案是「从属关系里不再有职业这一类，职业只由 `Agent.profession` 表达」，但这个答案是**删除的副产品，不是一次裁定**。若这不是所要的结果，需要主动推翻。

### 2. 四节说「`CultureDef` 六个字段只落地了一个」——今天落地了四个，但**类型不叫 `CultureDef`**

文化走的是 `TerrainTable`/`ResourceTable` 那条既有路线：**类型定义在 `ll-world`，数据由 `ll-mod` 从 `mods/lostland/cultures.json5` 装载，整张表注入世界生成**。因此代码里的名字是三个，不是一个：

| 本文档里的名字 | 代码里的名字 | 位置 |
|---|---|---|
| （文化的身份） | `CultureKind`（`ContentIndex` 新类型） | `crates/ll-world/src/culture.rs:72` |
| `CultureDef` 的字段载荷 | `CultureAttrs` | `crates/ll-world/src/culture.rs:98` |
| （注册表） | `CultureTable` | `crates/ll-world/src/culture.rs:232` |

`CultureAttrs` 的实际字段与本文档二节草图的对应关系：

| 本文档字段 | 落地情况 | 代码字段 | 真实消费者 |
|---|---|---|---|
| `building_materials` | ✅ 落地，但只有墙 | `wall_terrain` | `settlement.rs` 的 `house_tiles`/`ruin_tiles`（`:502`）。**地板仍恒为木地板**，代码注释写明「地板不影响可玩性」 |

- **文化在拓荒那一刻按「资源 + 地形 + 邻近据点 + 一点随机」抽一次，一个字节的种族数据都不读**（所有者裁定）。这与本文档设想的「种族 → 文化」方向相反，随机走独立的 `CHRONICLE_CULTURE_STREAM_ID`（约束 C3）。

### 3. 三节「文化偏好那一半是空的」已经不成立

上一节三、末尾写着「『文化偏好 × 周边资源点』里『文化偏好』那一半是空的——因为 `CultureDef` 完全不存在」。**今天两半都在了**：`SettlementSite::culture`（`crates/ll-world/src/settlement.rs:276`）带着文化，建材、选址加分、经济画像、建立者种族四条都读它。

**「战争认敌对」也落地了**：敌意是既有 1/8 掷骰的**加分项**，人口阈值与优势比两条闸门一字未动；`nearest_rival` 改名 `pick_target`，排序键加上敌意这一维，全表敌意为 0 时退化成与旧行为逐位相同的「最近优先」。

### 4. 二节「整套归属体系今天没有生产者」——**这一条完全没有变**

`affiliations: Vec::new()`/`wallet: 0` 仍然硬编码在两条唯一生产路径（`crates/ll-game/src/world.rs:544-545`、`crates/ll-mod/src/roster.rs:802-803`）；`OrgInstance`（`crates/ll-world/src/entity/org.rs:21`）仍然零生产构造点；`is_hostile` 仍然恒走「无势力 → 对谁都敌对」那条退化分支。

**文化批次让「文化」这一类有了内容表与据点级的生产者，但个体级的 `Affiliation` 一条都没有产出过。** `affiliation.rs` 的 `Culture` 变体文档已经如实写下这一点：「这一类现在有了真正的内容表与真正的生产者……**但个体级的 `Affiliation` 仍然没有生产者**……如实标注，不假装已接线。」

复核文档六节的三批拆分里，**第三批「世界生成期造 `OrgInstance`，给 `Agent`/名册真的填 `Affiliation`」仍未动**——那是让整套归属体系第一次有生产者的那一步，也是 P8（随从/指令/派工）的硬前置，见 [P7 → P8 交接清单](../handoff/p7-to-p8.md) 四节。
