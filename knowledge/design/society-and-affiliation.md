# 社会系统：归属、文化、聚落与地图结构

**冻结于** 2026-08-17。**实现阶段** P8（智能体经济与人口）为主，但**归属字段必须在 P3 建实体时就预留**，否则 P8 落地要改遍所有实体与存档。

所有数值一律整数，比例用千分比（见 [0002](../decisions/0002-integer-only-world-state.md)）。

---

## 一、核心：势力 / 宗教 / 行会 / 文化 是同一个结构

它们看起来是四个系统，实际只有一个数据结构、四种用途：

```rust
/// 一个实体对某个组织的归属与声望。
///
/// 势力、宗教、行会、文化用同一个结构，是因为它们对游戏逻辑提出的问题
/// 完全相同：「这个实体属于谁」「关系好到什么程度」。分成四套并行结构，
/// 就要写四遍偷窃判定、四遍交易折扣、四遍行为树条件。
#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct Affiliation {
    /// 归属类别。
    pub kind: AffiliationKind,
    /// 具体组织，指向注册表。
    pub org: ContentIndex,
    /// 声望，千分比。负值表示敌对。
    pub standing: i32,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub enum AffiliationKind {
    /// 势力：领土、法律、税收、兵役。
    Faction,
    /// 宗教：戒律、神祝、什一税。
    Religion,
    /// 行会：技艺、订单、垄断、会费。
    Guild,
    /// 文化：与生俱来，不索取任何东西，只塑造偏好。
    Culture,
}
```

一个实体持有 `Vec<Affiliation>`。**四类可以并存且互相冲突**——一个信奉海神的矮人铁匠工会成员，可能同时是山地王国的臣民，而海神教与山地王国正在交战。**这种张力是内容的来源，不是要消除的问题。**

### 各类提供什么、索取什么

| 类别 | 提供 | 索取 | 脱离方式 |
|---|---|---|---|
| **势力** | 领土通行、卫兵保护、法律仲裁 | 税收、兵役、忠诚 | 迁徙、叛逃（声望暴跌） |
| **宗教** | 士气、神祝能力、丧葬、庇护 | 什一税、遵守戒律、朝圣 | 改宗（原教声望暴跌） |
| **行会** | 技艺传授、订单渠道、垄断价 | 会费、质量标准、不得外传 | 退会、被逐 |
| **文化** | 偏好、建筑风格、命名、节庆 | **不索取**——文化是天生的 | 几乎不可改（除非幼年迁徙） |

**文化不索取任何东西，这是它与其余三者的根本区别。** 势力/宗教/行会是**加入**的，文化是**长成**的。

### 这个统一带来的直接回报

同一个 `Affiliation` 查询同时驱动：

- **偷窃判定**——物品的 `Owner::Faction(id)` 与拿取者的势力归属比对（见 [物品系统](item-system.md)）
- **交易价格**——同势力/同行会打折，敌对加价或拒绝交易
- **任务接取权**——行会任务只对会员开放，神殿任务看虔诚度
- **行为树条件**——`(has-affiliation? 'religion 'sea-god)` 直接可查
- **战争与结盟**——势力之间的 `standing` 就是外交关系

## 二、文化是一组权重，不是一个标签

这是「文化聚落」能真正长得不一样的关键。文化定义的**不是外观描述，而是生成时的权重**：

```rust
/// 文化定义。由注册表提供，mod 可自由新增。
pub struct CultureDef {
    pub id: NamespacedId,
    pub name_key: String,

    /// 建筑材料偏好，千分比权重。
    pub building_materials: Vec<(ContentIndex, i32)>,
    /// 选址地形偏好，千分比权重。
    pub site_terrain: Vec<(TerrainKind, i32)>,
    /// 经济结构偏好：农耕 / 游牧 / 商贸 / 采矿 / 渔猎。
    pub economy_weights: Vec<(EconomyKind, i32)>,
    /// 命名用的音节表与拼接规则。
    pub naming: NamingRules,
    /// 社会结构：家族 / 氏族 / 城邦 / 部落。
    pub social_structure: SocialStructure,
    /// 主流宗教倾向，千分比。
    pub religion_affinity: Vec<(ContentIndex, i32)>,
}
```

**同一套聚落生成器，喂不同的文化权重，产出完全不同的城镇。** 不需要为每种文明各写一个生成器——这与「本体即 Mod」是同一个思路：mod 加一份 `CultureDef` 就能加一种文明。

三种文化在同一片地形上的选址结果：

| 文化 | 选址权重 | 结果 |
|---|---|---|
| 海洋民 | 沿海 900、平原 200 | 沿海岸线串珠状分布 |
| 山地族 | 丘 700、山 600、森林 300 | 聚于内陆高地，彼此隔绝 |
| 草原游牧 | 草原 900、丘 400 | 分散、规模小、位置随季节变 |

## 三、地图结构层

在环面大陆的地形之上叠一层**结构层**。结构生成在地形之后，且**依赖地形**——不会把城建在深水里。

```rust
pub enum StructureKind {
    /// 聚落：村 / 镇 / 城，规模由人口决定。
    Settlement,
    /// 道路：连接聚落，降低移动代价。
    Road,
    /// 遗迹：可探索，有战利品与危险。
    Ruin,
    /// 地标：导航参照，无功能但有辨识度。
    Landmark,
    /// 资源点：矿脉、林场、渔场——经济的源头。
    ResourceNode,
}
```

### 道路是经济的骨架，不是装饰

道路降低 `move_cost`，因此**商队会沿路走**，因此**沿路的聚落更繁荣**，因此**繁荣的聚落又会修更多路**。

这个正反馈是城市自然分化出大小的机制，**不需要手工指定哪座城是首都**。

道路生成用聚落间的最小生成树 + 按贸易量加权的额外连边。**必须走环面最短路径**（`TorusSize::delta`），否则会出现绕半个世界的路。

### 资源点决定聚落的经济性格

聚落的经济结构 = **文化偏好 × 周边资源点**。海边的农耕文化会变成渔村，山里的商贸文化会变成矿业中转站。**性格是涌现的，不是指定的。**

## 四、宗教如何真正参与世界运转

### 戒律驱动行为

每个宗教有一组 `Tenet`（戒律），信徒违反会掉声望：

- 「不得食用兽肉」——影响 NPC 采购与市场需求
- 「日落后不得交易」——影响商店营业时间
- 「须以石建屋」——影响建筑材料选择
- 「不得与异教徒同席」——影响社交与任务接取

**戒律不是文本描述，是行为树能查询的条件。** 通过 Steel 脚本定义，与技能效果走同一套注册通道。

### 神殿是经济节点

神殿同时是：**什一税的收取点**（资金汇入）、**任务发布点**（用信众捐款悬赏）、**庇护所**（受伤或被通缉者的去处）、**神祝的来源**（消耗信仰值换增益）。

它有自己的钱包，因此**能像任何 agent 一样发布任务**——修缮神殿、护送朝圣者、讨伐异端。

### 宗教关系独立于政治边界

宗教的 `standing` 矩阵与势力的**分开维护**。这是这一层最有意思的张力来源：两个交战国的信徒可能同属一教，而同一国内的两教可能水火不容。

**这正是「宗教即势力」那个更省事的方案会丢掉的东西。** 矮人要塞验证了这条可行：它的信仰按「宗教团体」记录而非按政治文明记录，所以一个地精加入某宗教团体后，即便该宗教主要由别的文明信奉，他依然可以信那个神。

### 信仰强度是廉价标量

与钱包、名字同类：**神祇 ID + 虔诚度**。背景 NPC 按所属聚落的主流信仰 + 确定性随机生成，零额外开销。DF 用五档（狂热 / 虔诚 / 无标签 / 随性 / 半信半疑），可直接借鉴。

### 传播机制全部复用已有系统

| 宗教机制 | 复用什么 |
|---|---|
| 先知 | 具名 NPC，与领主、大商人同类，不是新概念 |
| 信徒转化 | **职业流动那套批量结算**，只是流动的字段从「职业」换成「宗教归属」 |
| 庙宇 | 结构 footprint 预留机制，信徒数过阈值就在骨架层占一块地 |
| 朝圣 | 商队的 progress 插值状态机，沿已有道路走一趟 |
| 宗教冲突 / 圣战 | 外交 + 战争系统，触发阈值换成宗教声望 |

**没有一条需要新写系统。**

### 必须避开的一个坑：新宗教要能在游玩中诞生

DF 的先知**只在世界生成的历史模拟阶段被创造**，进入游戏后没有再生成先知的机制——结果是实际游玩中新宗教基本无法自然产生。

这与本项目「经济、外交都要在游玩过程中持续演化」的哲学直接冲突。**不要照抄这一点**：把「先知诞生」设计成后台模拟层里一个**持续存在的低概率事件**——任何虔诚度极高的具名 NPC，每次结算都有极小概率「顿悟」成为新先知、拉出一个分支教派。

这是 DF 踩过的坑，可以直接绕开。

## 五、必须在 P3 就预留的字段

P3 要往 `WorldState` 加实体。**下面这些字段必须那时就在**：

```rust
pub struct Agent {
    // ... P3 的基础字段（位置、属性、时间轴条目）

    /// 归属列表。P3 可以留空，但字段必须存在。
    pub affiliations: Vec<Affiliation>,
    /// 钱包，最小货币单位的整数。见 agent-goals-and-economy.md
    pub wallet: i64,
    /// 当前职业，指向注册表。
    pub profession: ContentIndex,
}
```

**理由**：往 `WorldState` 加字段意味着存档迁移。存档格式在 P5 冻结——**P3 加是零成本，P8 加要写迁移链。**

## 六、LOD 兼容性（不可协商）

势力、宗教、行会的运作**必须能在 cohort 层批量进行**，否则与已定的三档 LOD（决策 21）冲突：

| 档 | 归属如何运作 |
|---|---|
| **近景** | 个体 agent 各自持有 `Affiliation`，个体决策 |
| **中景** | 按「同聚落 + 同归属」聚合，声望变动批量应用 |
| **远景** | 只维护组织级聚合量（总人口、总财富、组织间 standing），个体归属休眠 |

**关键**：组织级状态变化必须能用**闭式公式跳算**。声望自然衰减、税收累积、人口增减都要能一次性算完一整段时间，不能靠循环补跑——否则玩家离开三年再回来时会卡死。
