# 角色属性系统

**冻结于** 2026-08-17。**实现阶段** P3（战斗结算）与 P5（职业技能树），但**类型布局必须在 P2 建 `WorldState` 前定稿**。

骨架取自 DnD 并适配本作的时间轴调度与随从系统。**所有数值一律整数**，百分比一律用**千分比 `i32`**。

## 一、六项主属性

| 属性 | 驱动 |
|---|---|
| **力量 STR** | 物理攻击、负重上限 |
| **敏捷 DEX** | **时间轴速度**、闪避、命中 |
| **体质 CON** | 生命上限、抗性、耐力 |
| **智力 INT** | 魔法攻击、法力、学习速度 |
| **意志 WIS** | 精神攻防、抵抗、**视野半径** |
| **魅力 CHA** | **招募随从**、交易议价、随从士气 |

这套映射不是照搬 DnD，而是精确对上了本作已定的机制：三系攻击对应 STR / INT / WIS，随从招募系统对应 CHA，时间轴调度器对应 DEX，视野系统对应 WIS。

**调整值沿用 DnD 公式**：`modifier = (属性 − 10) / 2`（整数除法，向零截断）。这个公式经过四十年验证，且天然是整数运算。

### 成长上限

基础属性**硬上限 30**；装备与临时效果**可以突破**。

封顶让数值可预测、平衡可控；允许装备突破则保证封顶之后拾取好装备仍然有意义——否则一旦练满，所有装备上的属性加成瞬间作废，拾取的快感全没了。

## 二、三系攻防与护盾

| 系 | 攻击 | 防御 | 典型来源 |
|---|---|---|---|
| **物理** | 物理攻击力 | 护甲 | 武器、力量 |
| **魔法** | 魔法攻击力 | 魔抗 | 法术、智力 |
| **精神** | 精神攻击力 | 意志抗性 | 恐惧、魅惑、士气打击 |

**护盾**是独立于三系之外的第四层：临时护盾值优先承伤，可被「破盾」额外削减。

## 三、穿透属性

四种穿透，每种**两个分量**：

```rust
/// 穿透。固定值与千分比两个分量。
pub struct Penetration {
    /// 固定穿透值。
    pub flat: i32,
    /// 千分比穿透。
    pub permille: i32,
}
```

- 破甲 `armor_pen`
- 破魔 `magic_pen`
- 破意 `will_pen`
- 破盾 `shield_break`

**结算顺序必须定死：先减固定值，再乘千分比。**

```
有效护甲 = max(0, (护甲 − 破甲.flat) × (1000 − 破甲.permille) / 1000)
```

先固定后百分比意味着：固定破甲对**低护甲**目标收益更高，百分比破甲对**高护甲**目标收益更高——两条装备路线各有用武之地，而不是一条永远压倒另一条。

## 四、伤害公式：先固定减，再百分比，带下限

```
基础伤害 = 攻击力 + 加成
有效防御 = max(0, (防御 − 穿透.flat) × (1000 − 穿透.permille) / 1000)
减后伤害 = max(基础伤害 × 100 / 1000, 基础伤害 − 有效防御)   // 下限 10%
最终伤害 = 减后伤害 × 1000 / (1000 + 有效防御)
```

三段各有其职：固定减法让玩家能心算、让低伤多段攻击天然被重甲克制；百分比减免保证数值永不失控；**10% 下限保证不会出现「完全打不动」的死局**——那是单机 Roguelike 里最劝退的局面之一，玩家会直接删档。

## 五、幸运

幸运不直接加伤害，它**改变随机判定的形状**：

- **暴击率**：每点幸运 +5‰
- **优势掷骰**：幸运每满 20 点，判定时多掷一次取较优（DnD 的 advantage 机制）
- **掉落品质**：影响品质档位的权重分布
- **稀有事件**：触发权重

这样设计的好处是幸运**不会挤占战斗属性的定位**——它是「运气好的时候更好」，而不是「每次都多打十点」。

## 六、次级属性

### 战斗

命中 / 闪避 / 暴击率 / 暴击伤害 / 格挡率 / 格挡值 / 招架率 / 韧性（抗打断）/ 反击率 / 吸血（千分比）/ 伤害反弹

### 抗性

**元素**：火 / 冰 / 雷 / 毒 / 暗 / 光
**状态**：流血 / 中毒 / 眩晕 / 恐惧 / 魅惑 / 沉默 / 石化 / 减速

元素与状态分开，因为两者来源与解法不同：元素抗性主要来自装备材质，状态抗性主要来自体质与意志。

### 生存

生命 / 法力 / 耐力，各自的上限与回复速率。

### 感知与潜行（接视野与昼夜系统）

视野半径 / 夜视 / 潜行 / 察觉 / 噪音

### 社交与经济（接经济与随从系统）

议价（影响交易价格）/ 威望 / **领导力**（决定可带随从数上限）

### 移动

移动代价修正 / 地形适应（雪地、沼泽、山地）

## 七、衍生属性绝不进存档

这是本文档最重要的一条纪律。

```
derive_stats(基础属性, 装备, 状态效果, 负重) -> DerivedStats     // 纯函数
```

**衍生属性绝不存进 `WorldState`。**

存进去必然与来源不同步——脱了装备忘了减、buff 到期忘了移除，最终属性面板显示的数字与实际结算用的数字对不上。这类缺陷极难复现，因为它依赖一长串操作历史。

每次用时重算的成本，远低于维持同步的成本。

这也正好落在「意图—结算—效果」架构上：`resolve` 本就是纯函数且只读世界，属性派生天然属于它的内部。

## 八、判定：d20 + 确定性随机

```
掷骰 = DetRng::for_entity(世界种子, 实体ID, 事件计数).gen_range(20) + 1
成功 ⟺ 掷骰 + 调整值 ≥ 难度等级
```

沿用 d20 而非连续概率分布，因为**整数、可复现、玩家能心算**——玩家能算出「我需要掷 14 以上」，这是策略感的重要来源。

## 九、与时间轴调度的接口

```
行动耗时 = 基础代价 × 1000 / max(1, 有效敏捷)
```

整数除法，确定。`max(1, ...)` 防止敏捷被减到 0 时除零。
