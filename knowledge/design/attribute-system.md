# 角色属性系统

**冻结于** 2026-08-17。**实现阶段** P3（战斗结算）与 P5（职业技能树），但**类型布局必须在 P2 建 `WorldState` 前定稿**。

**落地状态**：部分落地。六项主属性的字段布局已实现为 `BaseStats`（`crates/ll-world/src/entity/stats.rs`），随 `Agent`（`crates/ll-world/src/entity/agent.rs`）与 `ThinPopulation::promote`（`crates/ll-world/src/entity/thin.rs`）使用。**注意**：代码字段名是 `willpower`，本文档写的是「意志 WIS」——两者指同一件事，但命名不同，未来对齐时需注意。调整值公式、三系攻防、护盾、四种穿透、幸运、次级属性、`derive_stats`、d20 判定均**尚未落地**，仍是纯设计。

骨架取自 DnD 并适配本作的时间轴调度与随从系统。**所有数值一律整数**，百分比一律用**千分比 `i32`**。

## 一、六项主属性

| 属性 | 驱动 |
|---|---|
| **力量 STR** | 物理攻击、[负重上限](item-system.md) |
| **敏捷 DEX** | **时间轴速度**、闪避、命中 |
| **体质 CON** | 生命上限、抗性、耐力 |
| **智力 INT** | 魔法攻击、法力、学习速度 |
| **意志 WIS** | 精神攻防、抵抗、**视野半径** |
| **魅力 CHA** | **招募随从**、交易议价、随从士气 |

这套映射不是照搬 DnD，而是精确对上了本作已定的机制：三系攻击对应 STR / INT / WIS，随从招募系统对应 CHA，时间轴调度器对应 DEX，视野系统对应 WIS。

**调整值沿用 DnD 公式**：`modifier = (属性 − 10) / 2`（整数除法，向零截断）。这个公式经过四十年验证，且天然是整数运算。

### 成长上限

基础属性**硬上限 30**；装备与临时效果**可以突破**。

封顶让数值可预测、平衡可控；允许装备突破则保证封顶之后拾取好装备仍然有意义——否则一旦练满，所有装备上的属性加成瞬间作废，拾取的快感全没了。

## 二、三系攻防与护盾

| 系 | 攻击 | 防御 | 典型来源 |
|---|---|---|---|
| **物理** | 物理攻击力 | 护甲 | [武器](item-system.md)、力量 |
| **魔法** | 魔法攻击力 | 魔抗 | 法术、智力 |
| **精神** | 精神攻击力 | 意志抗性 | 恐惧、魅惑、士气打击 |

**护盾**是独立于三系之外的第四层：临时护盾值优先承伤，可被「破盾」额外削减。

## 三、穿透属性

四种穿透，每种**两个分量**：

```rust
/// 穿透。固定值与千分比两个分量。
pub struct Penetration {
    /// 固定穿透值。
    pub flat: i32,
    /// 千分比穿透。
    pub permille: i32,
}
```

- 破甲 `armor_pen`
- 破魔 `magic_pen`
- 破意 `will_pen`
- 破盾 `shield_break`

**结算顺序必须定死：先减固定值，再乘千分比。**

```
有效护甲 = max(0, (护甲 − 破甲.flat) × (1000 − 破甲.permille) / 1000)
```

先固定后百分比意味着：固定破甲对**低护甲**目标收益更高，百分比破甲对**高护甲**目标收益更高——两条装备路线各有用武之地，而不是一条永远压倒另一条。

## 四、伤害公式：先固定减，再百分比，最后夹下限

```
基础伤害 = 攻击力 + 加成
有效防御 = max(0, (防御 − 穿透.flat) × (1000 − 穿透.permille) / 1000)
减后伤害 = (基础伤害 − 有效防御) × 1000 / (1000 + 有效防御)
最终伤害 = max(减后伤害, 基础伤害 × 100 / 1000)   // 下限 10%，最后夹
```

三段各有其职：固定减法让玩家能心算、让低伤多段攻击天然被重甲克制；百分比减免保证数值永不失控；**10% 下限保证不会出现「完全打不动」的死局**——那是单机 Roguelike 里最劝退的局面之一，玩家会直接删档。

### 为什么下限必须夹在最后一步

若把 10% 下限夹在百分比减免**之前**——即先算「减后伤害 = max(基础伤害 × 100/1000, 基础伤害 − 有效防御)」，再乘「1000/(1000 + 有效防御)」这个比例项——下限会被这最后一步的除法重新压扁：有效防御越大，比例项越小，被夹好的下限值也跟着被继续压低；有效防御足够大时，整数除法会把结果直接压到零，与上一段「10% 下限保证不会出现『完全打不动』的死局」这句话字面矛盾。**这个矛盾只在有效防御为零时才不出现——也就是下限从未真正起作用的唯一情形**，换句话说，那种顺序下的下限在任何本该生效的场合都是失效的。

两种顺序在**下限不生效的区间**（有效防御不足以把伤害压过下限）结果完全一致——比例项除法对单调递减的输入保持单调，讨论顺序在这个区间里无关紧要。两者只在**下限本该生效的区间**才分道扬镳，而把下限放在最后一步与比例项减免的结果取 `max`，是唯一让「10% 下限」这句话对任意防御值都成立的顺序。

实现见 `crates/ll-sim/src/combat.rs` 的 `damage_after_defense`，其函数文档给出了与此完全一致的推导，并有单元测试 `防御极高时伤害仍不低于攻击力的一成` 直接验证这条边界。

### 记录：这条公式曾经写反，是实现阶段发现的

冻结之初，本节字面顺序是「先夹 10% 下限，再乘比例项」，与本文档紧接着那句设计意图（10% 下限防止「完全打不动」的死局）直接矛盾——但这处矛盾在评审时没有被发现，因为逐字对照公式与代码的检查不会自己代入边界值。

它是在实现阶段被发现的：`combat.rs` 按字面顺序编码后，为「防御极高时伤害仍不低于攻击力一成」写单元测试，测试失败，回头查公式才发现问题出在公式本身的顺序，不是实现翻译错了。现已按代码的正确实现改写为上面这版。

**教训**：评审长期只问「实现是否满足设计」，没问「设计公式自身是否自洽」——一条公式即便被逐字翻译成代码，也可能在自己声明的设计意图下失效，而这类错误只在边界值（这里是防御趋于无穷大）才会暴露，普通量级的手算或走查很难撞上。设计文档里任何带上限/下限夹紧的多步公式，冻结前都应该反向代入极端边界值验算一遍，不能只检查语法通顺、意图读起来合理。

## 五、幸运

幸运不直接加伤害，它**改变随机判定的形状**：

- **暴击率**：每点幸运 +5‰
- **优势掷骰**：幸运每满 20 点，判定时多掷一次取较优（DnD 的 advantage 机制）
- **掉落品质**：影响品质档位的权重分布
- **稀有事件**：触发权重

这样设计的好处是幸运**不会挤占战斗属性的定位**——它是「运气好的时候更好」，而不是「每次都多打十点」。

## 六、次级属性

### 战斗

命中 / 闪避 / 暴击率 / 暴击伤害 / 格挡率 / 格挡值 / 招架率 / 韧性（抗打断）/ 反击率 / 吸血（千分比）/ 伤害反弹

### 抗性

**元素**：火 / 冰 / 雷 / 毒 / 暗 / 光
**状态**：流血 / 中毒 / 眩晕 / 恐惧 / 魅惑 / 沉默 / 石化 / 减速

元素与状态分开，因为两者来源与解法不同：元素抗性主要来自装备材质，状态抗性主要来自体质与意志。

### 生存

生命 / 法力 / 耐力，各自的上限与回复速率。

### 感知与潜行（接视野与昼夜系统）

视野半径 / 夜视 / 潜行 / 察觉 / 噪音

### 社交与经济（接经济与随从系统）

[议价](agent-goals-and-economy.md)（影响交易价格）/ **名望**（个人次级属性，来自事迹；与[职业声望](society-and-affiliation.md)同词根、不同量，二者的区分见该文档「职业声望是局部的」一节，原冲突清单条目 4，已裁定） / **领导力**（决定可带随从数上限）

### 移动

移动代价修正 / 地形适应（雪地、沼泽、山地）

## 七、衍生属性绝不进存档

这是本文档最重要的一条纪律。

```
derive_stats(基础属性, 装备, 状态效果, 负重) -> DerivedStats     // 纯函数
```

`装备`的具体贡献见[装备栏位与占位掩码](equipment-slots.md)，`负重`的分档规则见[物品系统](item-system.md)。`装备`如何把 `ItemDef.stat_bonuses` 转成属性加成，两份文档都未给出具体消费逻辑，见总索引冲突清单。

**衍生属性绝不存进 `WorldState`。**

存进去必然与来源不同步——脱了装备忘了减、buff 到期忘了移除，最终属性面板显示的数字与实际结算用的数字对不上。这类缺陷极难复现，因为它依赖一长串操作历史。

每次用时重算的成本，远低于维持同步的成本。

这也正好落在「意图—结算—效果」架构上：`resolve` 本就是纯函数且只读世界，属性派生天然属于它的内部。

## 八、判定：d20 + 确定性随机

```
掷骰 = DetRng::for_entity(世界种子, 实体ID, 事件计数).gen_range(20) + 1
成功 ⟺ 掷骰 + 调整值 ≥ 难度等级
```

沿用 d20 而非连续概率分布，因为**整数、可复现、玩家能心算**——玩家能算出「我需要掷 14 以上」，这是策略感的重要来源。

## 九、与时间轴调度的接口

```
行动耗时 = 基础代价 × 1000 / max(1, 有效敏捷)
```

整数除法，确定。`max(1, ...)` 防止敏捷被减到 0 时除零。
