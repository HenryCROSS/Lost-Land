# Agent 目标、任务发布与经济

**冻结于** 2026-08-17。**实现阶段** P8 为主，任务系统在 P5、行为树接线在 P7；但**钱包、职业、目标栈字段必须在 P3 预留**。

参考对象：矮人要塞的历史与经济模拟、Mount & Blade 的抽象战斗结算、Valheim 的持久化分层。

> **关于 Caves of Qud 的一处澄清**：Qud **没有**活的经济系统。它的价格是「物品基础价值 × 玩家自我属性与声望的浮动系数」，没有供需模拟、没有库存消耗；声望记在**势力**层面而非个体。它用两个巧妙的简化绕开了这个难题（货币与生存资源合一：水既是喝的也是钱；关系记在势力而非个人）。**它是「绕开问题」的范例，不是「解决问题」的参照。** 本设计走的是 DF 那条路。

## 零、性能纪律：真正的敌人是 O(n²) 互动，不是数据量

**这是本文档所有设计的总约束，先于一切具体机制。**

矮人要塞的 FPS death 有过明确的性能剖析结论：根本原因是**「所有生物互相检查视线」这套 O(n²) 系统**——哪怕是洞穴深处与玩家毫不相干的生物也在互相检查能否看见对方。寻路只占单帧处理时间的约 6%，不是大头；另一个大头是物品追踪。

**由此得出的纪律**：

| | 成本 |
|---|---|
| 每个 NPC 存一个钱包余额 | **极低**——几万个 NPC 各存一个 `i64`，内存微不足道 |
| 每个 NPC 有名字 | **极低**——名字是纯函数，见第十一节 |
| 每个 NPC 跟其他 NPC 逐个议价 / 互相检查 | **致命**——这是 DF 倒下的地方 |

所以「**居民只能通过本地行会交易**」这条规则（第三节）不是为省算力而作的妥协——它把 O(n²) 变成 O(n)，同时又恰好是中世纪行会的真实运作方式。**架构约束与世界观设定在此合二为一，这是好设计的信号。**

同理，本设计的一切「每个个体都有 X」都必须满足：**X 是数据或纯函数，不是需要与其他个体逐一交互的行为。**

## 一、核心循环：目标 → 需求 → 任务 → 悬赏

这一条循环把任务系统从「设计师手写的剧本」变成了「经济的副产品」。

```
Agent 持有目标（想要什么）
        ↓ 分解成需求（缺什么）
   能自己解决  →  行为树直接执行
   不能自己解决 →  发布任务，从自己钱包出悬赏
        ↓
   任务进公告板（城镇 / 行会 / 神殿）
        ↓
   别的 Agent 或玩家接取 → 完成 → 悬赏转账 → 目标推进
```

| | 传统任务系统 | 本设计 |
|---|---|---|
| 任务从哪来 | 设计师写死 | **NPC 的目标缺口自动生成** |
| 悬赏多少 | 设计师定 | **供需决定**——没人接就加价 |
| 任务用完了 | 加班写更多 | **经济在跑就一直有** |
| 玩家在干嘛 | 消费内容 | **参与经济** |

**玩家没有特权**：任务不会「等着玩家来做」，NPC 可能先接走。这是这套设计可信度的来源——世界不围着玩家转。反过来，玩家也能用同一套机制**发布任务雇佣 NPC**。

## 二、目标链

采用**完整目标链**：目标可分解出子目标，子目标不满足时继续往下分解。

```
目标：开一家铁匠铺
  ├ 需求：一处店面    → 有钱可买 → 直接买
  ├ 需求：铁锭 × 50   → 行会缺货 → 发布任务「收购铁锭」
  │      └ 接取者的子目标：采矿
  │            └ 需求：一把镐 → 发布任务「打造矿镐」
  └ 需求：行会资格    → 声望不足 → 发布任务「为行会跑腿」
```

**因果链是真实的**：完成「收购铁锭」会真正推进那个 NPC 的开店进度，不是加个计数器。

```rust
pub struct Goal {
    /// 目标类型，指向注册表（mod 可扩展）。
    pub kind: ContentIndex,
    /// 目标参数（开哪种店、要多少铁）。
    pub params: Vec<i64>,
    /// 已推进进度，千分比。
    pub progress: i32,
    /// 优先级，决定钱包紧张时先满足哪个。
    pub priority: i32,
}
```

**目标链深度必须有上限**（建议 4 层）。否则一个需求可以无限展开成任务树。触顶时 agent 放弃该目标并降低其优先级——**放弃是正常行为，不是失败**。

### 任务池的规模封顶（比深度上限更根本）

深度上限只防单条链失控，**真正决定任务池规模的是「谁有资格往里写」**：

- **背景 NPC 的需求不直接进任务池**，先聚合进所属聚落的经济层（缺粮就是聚落库存/需求数字的一部分，本来就在结算）
- **只有聚落层判断「这个缺口靠常规商路解决不了 / 太紧急」，才生成一条任务**
- **具名 NPC 与行会可以直接发个性化任务**，不经过聚合——这才是有叙事质感的任务来源

**于是任务池的量级被死死限制在「聚落数量级」，不随人口膨胀。** 一万人的世界，任务池只有几十到几百条。

### 统一的 Task 结构

「NPC 执行自己的任务」与「NPC 发布任务给别人」**不是两个系统，是同一个结构的两种状态**：

```rust
pub struct Task {
    /// 执行者。`None` 表示开放认领，进入公共任务池。
    pub assignee: Option<EntityId>,
    pub kind: ContentIndex,
    pub reward: i64,
    pub location: TorusPos,
    pub deadline: Tick,
}
```

- `assignee == Some(自己)` → 这是他的私人任务队列，驱动日常行为
- `assignee == None` → 这是他发布出去、等人认领的任务

**玩家看到的任务板，只是任务池里「尚未认领、且叙事权重够得上展示」的那一部分**——不需要另做一套平行的手写任务系统。

> **需要一道趣味性过滤**：若玩家任务板与内部经济任务完全共用一个池子，会被「运 50 单位铁矿」这类条目刷屏。按叙事权重设阈值，只有超过阈值的才浮现给玩家。

## 三、贸易：枢纽辐射，不是个体互市

**这是整个经济系统里最关键的一条计算量决策。**

```
居民 ←→ 本地行会 ←→ 商队 ←→ 其他领地的行会 ←→ 那里的居民
        （唯一的本地交易对手）    （唯一的跨领地通道）
```

**领地内的居民只与本地行会交易，居民之间不互市。** 跨领地贸易由行会之间派遣商队完成。玩家可以与行会交易，也可以在路上与商队交易。

### 为什么这样做

| | 个体互市 | 枢纽辐射 |
|---|---|---|
| 领地内交易配对 | N 个居民两两议价 → **O(N²)** | 每人对行会一次 → **O(N)** |
| 一万居民的量级 | 约 5000 万次配对 | **一万次** |
| 价格从哪来 | 从个体成交价涌现，难收敛 | **行会按属性定价**，一个节点一个价 |
| 跨领地 | 每个商人各跑各的路线 | 行会间的**稀疏路线网** |

**而且这不是为省算力编的设定**——中世纪的行会本来就垄断本地贸易、统一定价。省算力与真实性在这里同向。

### 行会如何定价

行会按下列属性算出本地价格，**全整数、千分比**：

```
本地价 = 基础价
       × 库存系数（库存少则涨）
       × 需求系数（本地消费速率）
       × 行会政策（垄断度、保护主义）
       × 商路系数（进货成本，受商路安全影响）
```

行会**买入价低于卖出价**，价差是它的利润，也是它派商队、雇护卫、维持仓库的资金来源。

### 玩家的两个交易对手

- **行会**：价格稳定、货品齐全、但吃价差
- **路上的商队**：价格随机性大、货品随路线而定、**可能更便宜也可能更贵**，且有风险

这给了玩家真实的选择，而不是「到处都是同一个商店」。

## 四、钱包

```rust
/// Agent 的现金。最小货币单位的整数，绝不用浮点。
pub wallet: i64,
```

钱包驱动一切：买原料、付悬赏、交税、交会费、交什一税。**钱不够时目标停滞**，这正是 agent 会去接别人任务赚钱的原因——经济闭环由此形成。

### 货币守恒与回收汇

智能体经济最容易失控的方式是**货币无限累积**。必须有回收汇：税收、会费、什一税、装备维修与损耗、通行费与住宿费。

**回收汇不是惩罚机制，是防通胀的水闸。** `ll-econsim` 压测的首要指标就是货币总量是否发散。

## 五、致富、破产，与土匪

居民的钱包会真实地涨落，而**贫富直接改变行为**：

```rust
pub enum WealthTier {
    /// 破产：负债或现金见底，无法维持职业。
    Destitute,
    /// 温饱：勉强维持。
    Subsisting,
    /// 小康：有余力投资、发布任务。
    Comfortable,
    /// 富裕：可雇人、开分店、影响行会决策。
    Wealthy,
}
```

- **富裕者**发布更多、悬赏更高的任务，投资新店铺，在行会里话语权更大
- **温饱者**只维持日常，偶尔接任务补贴
- **破产者**付不起会费 → 被行会除名 → **失去唯一的合法交易渠道**

### 破产 → 土匪：一条有牙齿的负反馈环

被行会除名的居民做职业审计时，**唯一还够得着的「职业」是土匪**——它不需要行会资格、不需要学徒费、不需要师傅。

```
经济下行 → 居民破产 → 被行会除名
    → 审计后转职土匪 → 劫掠商队
        → 商路不安全 → 行会加价、减少派遣商队
            → 本地物资更紧张 → 更多人破产
                ↓
   直到：势力雇佣护卫 / 玩家清剿 / 行会提高收购价重新吸纳
```

**这一个循环同时解释了三件事**——为什么世界上有土匪、为什么需要护卫、为什么剿匪是有意义的玩法。三者都不用单独设计，全是经济的自然结果。

**这也是「破产」在本设计里不只是一个数字状态的原因**：它有出口，而那个出口会反过来伤害经济。

## 六、职业审计

采用**受限转行**。

```
每季度（时间轴事件）：
  1. 结算过去一季收支
  2. 与本地行会公布的其他职业平均收益比较
  3. 若 收益差距 > 阈值
     且 付得起学徒费
     且 有人能教（同城有该职业师傅 / 行会名额）
     且 年龄与属性允许
     且 性格允许（保守者阈值更高）
        → 转行

  例外：破产且被行会除名者，可无条件转为土匪
       （土匪不需要资格、学费与师傅——这正是它成为兜底出口的原因）
```

### 真正的作用

不是「让 NPC 显得聪明」，而是**让经济自己找平衡**：

```
铁匠太多 → 铁器供过于求 → 行会压低收购价 → 铁匠收益下降
        → 部分铁匠转行 → 铁匠变少 → 收购价回升
```

**不需要任何全局调控器。这是智能体经济真正开始「活」的那一刻。**

### 为什么「受限」而不是「自由」

自由转行会造成**集体振荡**——全镇铁匠同季度一起转行当农民，下季度又一起转回。摩擦（学徒费、师傅、名额、年龄）是阻尼器，让经济平滑趋向平衡而不是来回抖。

这也顺带产生了「学徒」「师傅」「行会名额」这些天然的任务与社会结构。

### 硬约束

- **必须是时间轴事件，不能每帧算。**
- **远景区域按 cohort 批量审计**：只算「该职业群体的平均收益」并按比例迁移人数，个体审计只在近景进行。
- **审计用的随机必须是 `DetRng::for_entity`**，否则读档后所有人的转行决策会分叉。

## 七、商队

商队是**行会派出的移动 agent**，不是特效。

```rust
pub struct Caravan {
    /// 商队本身也是 agent，有钱包与目标。
    pub agent: EntityId,
    /// 派出方行会。
    pub owner_guild: ContentIndex,
    /// 货物清单。
    pub cargo: Vec<ItemStack>,
    /// 路线：起点、终点、途经点。
    pub route: Vec<TorusPos>,
    /// 风险偏好，千分比。高者走近路，低者绕行安全区。
    pub risk_tolerance: i32,
}
```

商队从便宜的行会买、往贵的行会卖，**在套利的同时磨平价差**。

商队沿道路走（`move_cost` 更低），因此**路网决定贸易流向**，因此**沿路聚落更繁荣**——与 [社会系统](society-and-affiliation.md) 的道路正反馈是同一个循环。

**商队会被劫**，这是第五节那个负反馈环的关键一环。

### 途中报价：从机会成本推导，而非按路程插值

一个自然的做法是让途中价格在起点价与终点价之间按路程线性插值。**那会给出对的形状，但给错了理由**——它是几何决定的，商队走到半路就一定报中间价，不管路上发生了什么。

而且它在经济上有一处说反了：一支刚出发、货满仓的商队凭什么便宜卖？它完全可以把货拉到目的地卖全价。**它愿意便宜卖的唯一理由是「拉过去还要花钱、还有风险」。**

### 分两档实现，先简后繁

**第一档（MVP，先做这个）——路程插值**：

```
行商报价 = lerp(出发时的起点行会价, 目的地行会当前价, progress) + 风险挂钩的利润率
```

起点价用**出发时冻结的值**（那是他真实的成本基础），目的地价用**当前值**（那是他将要拿到的）。这个不对称是对的。利润率与路途距离和危险度挂钩，于是「长途商人东西贵」有了机制解释，不用硬编。

**第二档（升级，等土匪与商路安全度真正实现后）——机会成本推导**：

```
商队最低卖价 = 目的地行会价 − 剩余运输成本 − 剩余风险损失期望
商队最高买价 = 起点行会价   + 已投入运输成本
```

**这会自然长出插值的形状**（刚出发时剩余成本高故底价低，快到时剩余成本趋零故报价逼近目的地价），**但每个数字都有原因**，于是它会对真实事件做出反应：

| 路上发生的事 | 纯插值 | 机会成本模型 |
|---|---|---|
| 前方商路出现土匪 | 无变化 | **风险溢价上升 → 报价变高** |
| 商队被劫、损失货物 | 无变化 | **需弥补损失 → 报价变高** |
| 快到终点仍未售罄 | 无变化 | **拉回更亏 → 甩货降价** |
| 该路段土匪被清剿 | 无变化 | **风险下降 → 报价变低** |

运算量与插值相当（全整数、几次乘除），但玩家能感觉到**这支商队经历过什么**。

**白送的两个玩法**：

- **情报有价值**——知道前方有土匪的玩家可以预判商队即将涨价
- **玩家能主动影响价格**——清剿一段商路上的土匪，那条路上所有商队的风险溢价都会下降。玩家的行动通过经济模型产生了**可见的后果**，而不是任务日志上的一行字

**剩余风险损失期望**由路段的土匪活跃度、商队护卫强度、风险偏好共同决定，全部整数。路段安全度本身是世界状态的一部分，随劫掠与清剿事件更新。

**两档的数据结构兼容**，第二档是第一档的精修，不是替代——它多做的事只有一件：把「剩余成本」与「剩余风险」显式算出来，于是能对**路上发生的事**做出反应，而插值只对两端行会的价格变化做出反应。

### 商队抵达时闭合经济环

商队到达目的地后把剩余库存**倒进目的地行会的库存**。这一步会真实地拉低目的地价格、抬高起点价格（起点少了货）——**这正是「盈余流向短缺」的网络流模型在执行层的样子**。商队不是独立的经济系统，它是那套供需结算的搬运工与具象化载体。

## 七之二、背景与前景：公式与模拟的分界

这是把「每个 NPC 都有钱包、都能破产致富」做到**成本极低**的关键，也是**最容易漏掉细节的地方**。

### 三档精度

| 档 | 谁 | 怎么算 |
|---|---|---|
| **背景层** | 绝大多数 NPC | **批量公式**：`钱包 += 职业基础收入 × 聚落经济健康度 + 确定性随机波动`。对整个聚落人口一次算完，成本与人口线性且可向量化。**不跑任何 AI 决策。** |
| **前景层** | 玩家附近 / 正被观察的 NPC | 跑真实决策（要不要买、要不要接任务）。数量天然被玩家视野限制，不会失控。 |
| **具名层** | 重要 NPC、玩家深度互动过的 | 永久高精度，数量由内容设计控制 |

**「人人都能破产致富」完全成立**——因为批量公式里天然有随机性与分化，而成本只与人口成线性。

### 背景 NPC 的行为也是公式

职业直接对应一条**固定任务模板**：农民 = `[耕地 → 播种 → 照料 → 收获 → 卖给行会]`。用 progress 插值驱动：知道现在第几天、整条序列多久，直接算出他应该在哪一步，**不逐 tick 模拟**。

商队同理——出发时刻、路径总长、已过时间三者就能插值出当前位置与状态。**玩家看不见时，背景 NPC 本质上是公式，不是活跃对象。**

### 升格与降级（最容易做漏的一环）

背景 NPC 在下列情况**升格**为真正被模拟的活跃对象：

- 玩家靠近到可见范围
- 模板走不通（例如「卖给行会」但行会价格崩了 / 不收货）——此时未完成的步骤从私人队列**溢出成一条公共任务**
- 遭遇意外（被劫、被攻击、被玩家雇佣或对话触发分支）

**升格后必须真正持久化状态**，不能再靠公式重算——因为他的轨迹已经偏离了确定性生成的结果。意外结束（死亡、逃脱、货物被抢完）后才可能**降级**回背景层。

> **这条升格/降级的触发与收尾逻辑，是整套系统里最容易漏掉细节的地方。** 漏了会表现为：玩家眼前的 NPC 走位诡异、离开再回来状态跳变、或者被劫过的商队回到公式轨道后「货物又变回来了」。P8 实现时须为它单独设计并写测试。

### 棘轮问题：必须把「被记住」与「被模拟」拆开

**若「升格」是单向的，系统就有一个棘轮**：玩上百小时后，被玩家碰过的 NPC 累积成几千个全精度对象，廉价的背景层不断萎缩，性能持续劣化且不可逆。

**根因是把两件不同成本的事混成了一个开关**：

| | 单位成本 | 规模上限 |
|---|---|---|
| **被记住**（有持久状态） | 极低——存一个偏移量 | **可以是几百万** |
| **被模拟**（每回合跑决策） | 高 | **必须有界** |

**升格只永久授予「被记住」；「被模拟」仅在相关期间维持。**

#### 偏移量 + 重定基准

沿用 Valheim 的原则——**能重算的不用存，被动过的才存**——从地形搬到 NPC：

```
NPC 钱包 = 批量公式(种子, ID, 距基准时刻的时长) + 偏移量
```

- 玩家给了他 500 金 → 只存 `wallet_delta: +500`，他**立刻可以回到批量公式**，公式照跑、偏移照加
- 长期未交互 → **重定基准**：当前值快照成新基准，偏移归零，之后继续纯公式驱动
- 具名 / 剧情相关的 NPC 可**钉住**，永不重定基准

再加一道 **LRU 上限**：同时处于「被模拟」的 NPC 数量硬性封顶，最久未交互者先被重定基准。**无论玩多久，昂贵档的规模恒定有界。**

#### 什么才真正需要完整持久化

**轨迹本身偏离了公式的 NPC**——破产后转为土匪并离开原聚落、被玩家雇为随从、成为具名势力人物。这不是一个偏移量，是另一条人生轨迹。

这类数量天然稀少（受破产率、雇佣上限、剧情密度约束），可以真正存下来，不构成棘轮。

**判断标准**：能用「公式 + 偏移」表达的，就不要升格为完整持久化。

## 八、惰性追赶的边界

行会与商队的决策**必须是事件驱动而非 tick 驱动**——行会自己决定下一次进货/定价/派遣的时刻并插入时间轴。枢纽模型让事件数量进一步下降：**决策主体从「每个商人」变成「每个行会」**，一百个领地就是一百个决策主体，而不是一万个。

远景区域降级为 cohort-only + 粗时间步（一周一步），个体决策暂停；玩家靠近时解压回个体，缺失的个体历史用**追溯生成**补齐。

## 十、`ll-econsim` 的验收指标

空跑 100 年后，下列指标**必须不发散**：

| 指标 | 判据 |
|---|---|
| 货币总量 | 不单调增长（回收汇有效） |
| 物价指数 | 波动有界，无恶性通胀或通缩 |
| 人口 | 不归零、不指数爆炸 |
| 职业分布 | 各职业占比稳定，无集体振荡 |
| **土匪比例** | **有涨落但不吞噬整个世界**——若土匪单调增长，说明破产出口失去了回流路径 |
| 任务积压 | 未完成任务数不无限增长（否则悬赏定价机制失效） |

**没有这个工具，无法判断经济是否稳定。** 它与地图编辑器同等优先级。
