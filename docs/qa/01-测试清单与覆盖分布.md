**目前没有发现"有真实逻辑分支却完全零测试"的模块**——这是一个积极信号，但注意这只覆盖
到 P3 阶段已落地的代码，P8 等后续阶段的逻辑一旦写进这几个占位结构，必须同步补测试，
否则会重演 `error.rs` 那种"能编译就当完事"的疏漏。

## 4. 属性测试（proptest）覆盖的模块

以下文件里的测试函数使用 `proptest!` 宏而非具体断言用例（用中文测试名里的"任意"
"恒""都"等词与源码内 `use proptest::prelude::*` 双重确认）：

| 文件 | 属性测试数 | 守护的不变量 |
|---|---:|---|
| `ll-core/tests/torus_blackbox.rs` | 5 | 环面距离对称、三角不等式相关性质、位移绕回 |
| `ll-core/tests/ident_blackbox.rs` | 1（"任意输入要么被拒要么原样往返"） | 命名空间标识符解析的健壮性 |
| `ll-core/tests/determinism.rs` | 0（这是黄金基准回归，非属性测试，见 `02` 文档） | — |
| `ll-platform/tests/input_blackbox.rs` | 0（具体用例，非 `proptest!`） | — |
| `ll-render/tests/atlas_blackbox.rs` | 部分 | 畸形图集元数据不崩溃 |
| `ll-render/tests/sprite_blackbox.rs` | 3 | Y 排序全序性质（反对称、传递） |
| `ll-sim/tests/timeline_blackbox.rs` | 部分（"任意调度序列下弹出总数等于调度总数"等） | 时间轴弹出顺序单调、序列化往返 |
| `ll-world/tests/fov_blackbox.rs` | 4（全部） | FOV 对称性——见 `02-测试类型与局限.md` 的专门小节 |
| `ll-world/tests/noise_blackbox.rs` | 6（全部） | 可平铺噪声接缝连续性、多倍频不溢出 |

`proptest` 默认每个属性跑 **256 组随机用例**（未在仓库任何位置发现自定义
`proptest.toml` 或 `ProptestConfig` 覆盖默认值，已用 `find . -iname proptest.toml`
确认不存在），所以单次 `cargo test` 实际执行的随机用例数远超"308 个测试"这个数字
表面暗示的规模——`fov_blackbox.rs` 的 4 个测试函数单次运行就至少覆盖
4 × 256 = 1024 组随机地形/坐标组合（"墙格与原点的可见性对称"内部还有双重循环，
实际探测的具体点对数量更多）。

## 5. 基准测试（criterion）

仅 `crates/ll-core/benches/torus.rs` 一个基准文件，覆盖环面坐标运算的性能。
`ll-render`、`ll-sim`、`ll-world` 的 `Cargo.toml` 均未声明 `criterion` 依赖或
`benches/` 目录（`ll-world` 的 `Cargo.toml` 注释里明确写了原因："本 crate 没有
`benches/` 目录，声明了也不会被用到……真出现性能问题时再补"）。

`cargo test --workspace` **不会**运行这个基准——`ll-core/Cargo.toml` 显式给
`[[bench]] name = "torus"` 加了 `test = false`，注释写明理由是避免
`cargo test --all-targets` 把基准当测试跑一遍拖慢 CI。这意味着这个基准目前
**只能靠人手动跑 `cargo bench` 触发**，CI 完全不知道它的存在，见
`03-CI门禁对照与补齐方案.md` 与 `04-覆盖率与缺失测试层.md` 中"性能回归"一节。
