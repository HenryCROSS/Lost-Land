# 迷途大陆 / LostLand — 总纲设计规格

- 日期：2026-08-16
- 状态：待评审
- 范围：全项目架构总纲。各阶段（P0–P10）在本文批准后各自产出独立的实施计划。

---

## 1. 项目定位

用 Rust 从零构建一款**像素风、日式二次元画风、跨平台（Windows / Linux）的传统 Roguelike**。

不使用任何游戏引擎。只使用不接管主循环、不规定架构的**基础库**。所有依赖必须是宽松开源许可（MIT / Apache-2.0 / zlib / OFL），**不得引入任何存在商用收费或传染性许可（GPL/AGPL）的依赖**。

核心玩法：单主角操控 + 可招募随从，同图直接行动的回合制战斗，敏捷驱动的非线性出手顺序，丰富的职业与技能树，网状任务系统，以及一个持续演进的智能体经济世界。

## 4. 核心架构：意图 — 结算 — 效果

整个游戏逻辑是一条严格的单向数据流。**`apply` 是全局唯一能修改世界的地方。**

```
玩家输入 ─────────────────→ Intent ─┐
                                     │
随从/敌人 行为树 (.scm) ───→ Intent ─┼─→ resolve(&WorldState, Intent) -> Vec<Effect>
                                     │      纯函数 · 只读世界 · 可并行 · 出错降级
Mod 注册的技能 / AI ───────→ Intent ─┘                    │
                                                          ↓
                                            apply(&mut WorldState, Effect)
                                              唯一写入口 · 单线程 · 无逻辑 · 极短
```

### 四个概念

- **`WorldState`** — 完全可序列化、**不含任何指针 / 引用 / 闭包 / trait 对象**的纯数据。世界的全部真相。
- **`Intent`** — 「我要向东走」「我要对 (x,y) 释放 3 号技能」。纯数据，可序列化。玩家和 AI 都只产出它。
- **`resolve`** — `fn(&WorldState, Intent) -> Vec<Effect>`。纯函数，只读世界。命中判定、伤害公式、技能效果都在此，可调用 Steel。
- **`Effect`** — 「实体 7 生命 -12」「实体 3 移动到 (5,9)」「向时间轴插入事件」。纯数据。
- **`apply`** — `fn(&mut WorldState, Effect)`。唯一写入口，单线程，不含任何游戏逻辑。

### 这个结构一次性解决的问题

| 需求 | 解决方式 |
|---|---|
| 模式3 自由读档 | 存档即序列化 `WorldState`，无隐藏状态 |
| 函数式代码风格 | `resolve` 承载主体逻辑且天然是纯函数 |
| 多线程不阻塞 | `resolve` 只读，可直接 `rayon` 并行；`apply` 极短不成瓶颈 |
| 脚本沙箱 | 脚本只能返回 `Effect`，物理上无法触及世界 |
| 大量实体优化 | `Effect` 可累积、排序、合并后批量应用 |
| 确定性重放 | 记录 Intent 流 + 随机种子即可完整复现一局 |

### 硬性约束

- **C1** — Steel 脚本**不得持有任何跨帧的隐式状态**——任何需要在下一次调用中还记得的东西，必须经由明确注册的读写 API（脚本状态存储：`state-set!`/`entity-state-set!`/`state-get!`/`entity-state-get!`/`state-get-foreign`）显式存入 `WorldState`，不得依赖 VM 自身的 `define`/`set!`/闭包捕获来跨调用留存。任务进度、技能冷却、AI 记忆、行为树当前节点，全部经这条路径落地。脚本本身除了这条显式通道之外应被当作纯函数对待：给定相同的 `WorldState`（含脚本状态）与相同输入，必须产出相同结果。**VM 必须可随时从零重建，且重建不需要任何迁移步骤**——这是脚本状态存储落地后从「能力声明」升级成的「可测试断言」，见下方修订说明。
- **C2** — 时间轴队列中只能存放纯数据（actor id + 行动类型 id + 参数），**禁止闭包与裸指针**。
- **C3** — 所有随机性必须来自**按实体 ID 派生的确定性流**：`rng = hash(世界种子, 实体ID, 该实体事件计数)`。**禁止使用全局 RNG 流**，否则并行化与读档重放都会分叉。
- **C4** — 后台推进离屏世界时，**必须推进到一个确定的世界时刻 T**，不得「能跑多少跑多少」。否则玩家思考时长会污染世界状态。
- **C5** — **禁止让 `HashMap`/`HashSet` 的迭代顺序参与任何逻辑判断**。无序容器的迭代顺序在不同运行、不同平台之间不保证一致，甚至同一进程内两次构造内容相同的容器也可能产出不同的键序（**P4 期间已实测确认**：两个内容相同的 `HashMap` 给出了不同的迭代顺序）。让它参与逻辑判断，后果与违反 C3 同源——都是把一个非确定性的隐藏输入源带进了 `resolve`/`apply` 链路——只是发作得更慢：重放不会立刻报错，而是在几百 tick 后悄悄分叉，**测试不会变红，只会在某天状态哈希对不上**。需要顺序参与逻辑时改用 `BTreeMap`/`BTreeSet`，或对键先显式排序再遍历；`HashMap`/`HashSet` 只允许用于 O(1) 单键查找，禁止遍历其产出的顺序去影响世界状态。
- **C6** — **同一根线程上，全部 Steel 引擎的构造必须发生在全部脚本编译之前。** 一旦这根线程上编译过任何脚本源码（`ScriptEngine::load_source`），就**不得再在这根线程上构造引擎**。真的需要在编译之后再造引擎时，唯一被认可的做法是**换一根新线程**（steel-core 的引擎级状态是线程局部的，新线程等于一份没有被任何编译动作污染过的全新内核），不是想办法绕过检查。这条约束由机器强制：`ll_script::host::ScriptEngine::new` 违反时直接 panic 并点名，不是 `debug_assert!`。理由是 [ADR 0028](../../../knowledge/decisions/0028-steel-engine-construction-memory-corruption.md) 实测定位的上游内存安全缺陷——`steel-core` 0.8.2 **只在「先编译、后构造」这个相邻关系上**读到野指针（只构造 16000 次不崩、只编译 4800 次不崩、两者交替才崩），而崩溃点在 `Engine::new_sandboxed()` 内部编译 steel 自己的 prelude 时，与我们写了什么脚本毫无关系。**这条规则的失效方式极其隐蔽**：将来任何人新增一处引擎构造点，代码照常编译、测试照常绿，偶发的进程级崩溃会悄悄回来，而且崩在与新增点毫无关系的地方——因此必须当场拦住，而不是靠约定与代码评审。落地形态见 [ADR 0029](../../../knowledge/decisions/0029-engine-construction-phase-precedes-compilation.md)。

> **[2026-08-18 规格修订]** 新增 **C5**。这条规则此前只以约定俗成的形式活在代码注释里——五处引用三比二地误标为 C3/C4，另有一处把 C3 本身的字面定义误标成 C4（详见 `knowledge/audit/worklist.md` W-05）——却从未进入本节这份"唯一真相源"。这是 [ADR 0013](../../../knowledge/decisions/0013-ledger-vs-adr-discipline.md) 记录的失败模式的又一次重演：一条被反复引用、被当作硬约束执行的规矩，只因为每次都靠派活时手写进指令、没人把它写回真相源，漏写一次就等于它没发生过。

> **[2026-08-19 规格修订]** 修订 **C1**。原文只有「不得持有隐式状态」「VM 必须可随时从零重建」两句能力声明——落地脚本状态存储（`knowledge/design/script-state-storage.md`）之前，**没有任何显式机制存在**：任何跨帧状态都只能是隐式的（活在 VM 内存里，没有明确 API），「隐式」这个限定词因此形同虚设，原文事实上无法被违反,也无法被测试钉住。脚本状态存储落地后，「显式」第一次有了具体所指（`state-set!` 系列 API），修订版把两处能力声明升级成两条可测试的断言：①「给定相同输入产出相同结果」（呼应约束 C3 的确定性要求，可以被单元测试直接断言）；②「重建不需要任何迁移步骤」（比单纯「可以重建」更强——重建后不应该有任何需要恢复的东西，因为脚本本该没有值得迁移的东西）。落地方式：存档/读档边界强制重建全部 `ScriptEngine` 实例（`ll_script::host::rebuild_all_engines_after_load`），不做「先检测是否需要重建再决定」——那需要 `tools/ll-datacheck` 这类尚不存在的静态检查工具，强制重建绕开了这条没有可靠检测手段的路。

> **[2026-08-22 规格修订]** 新增 **C6**。与 C5 同一种情形——一条必须被机器强制、否则会以「测试照常绿、崩溃随机回来」的方式失效的硬规则。区别在于 C6 从第一天起就带着强制手段落地（`ScriptEngine::new` 里的断言），不是先当约定用一阵再补写回真相源。它同时改变了 mod 装载管线的作用域语义：作用域单位从「脚本文件」升格成「mod」（同一个 mod 的多个 `entry_points` 共用一个引擎，跨 mod 仍各用各的），见 ADR 0029。

## 5. Crate 分层

采用 Cargo workspace。**依赖方向由 Cargo 物理强制单向**——这是「高内聚低耦合」的机器强制版本，也让并行开发时 crate 边界天然成为任务边界。

```
crates/
  ll-core       纯数据类型：环面坐标、时间、命名空间 ID、确定性 RNG、错误。零依赖
  ll-platform   winit 窗口、输入、文件系统、线程池、日志
  ll-render     wgpu 精灵批渲染、图集、相机、图层、Y 排序、跨接缝绘制
  ll-text       cosmic-text 排版 + glyphon 渲染（wgpu） + 思源黑体 Source Han Sans + Fluent i18n
  ll-audio      kira 封装 + 预留脚本合成接口
  ll-world      WorldState、环面地形、FOV、世界时钟、昼夜四季、分区
  ll-sim        Intent/Effect/Apply、时间轴调度器、战斗结算
  ll-script     Steel VM 宿主、绑定层、沙箱守卫、热重载
  ll-mod        mod 发现、清单解析、依赖拓扑排序、资产 VFS、内容注册表
```

## 7. 世界模型

### 7.1 环面拓扑

**大陆世界地图层**为**真环面**，东西南北四面全连通，坐标取模。

> **适用范围（避免歧义）**：环面拓扑仅适用于大陆世界地图这一层。**进入具体区域后的分区场景是有界局部地图**，四周由地形自然收边，不做环绕。两层坐标系通过明确的转换接口衔接，分区场景在大陆图上的锚点使用环面坐标。

> **本节取代说明（2026-08-18，坐标系与离散层设计）**：本节原文与已落地代码（`ll_world::state::WorldState`/`chunk::ChunkGrid`/`generate::generate_terrain`）隐含同一个假设——**整个世界是一整张连续瓦片图，一次性生成、整体常驻**。这条假设已被 [坐标系与空间模型](../../../knowledge/design/coordinate-system-and-layers.md) 取代，理由与后果如下，正文其余部分（环面数学、可平铺整数噪声、跨接缝绘制、气候条带）**不受影响，原样有效**。
>
> **为什么要换**：世界历史生成（P7）要产出几十王朝、几百聚落这个量级的分布；现有 512×320 单张环面图按一个聚落所需活动范围粗估只装得下四十来块，连零头都不够。矮人要塞式的地下城/建筑内部楼层需求，此前也从未有过坐标形状规划。
>
> **换成什么**：地表（`Space::Surface`，`z = 0`）本身**仍然是本节描述的真环面、真无缝**——环面数学（`TorusSize`/`TorusPos`）、可平铺噪声（`TileableNoise`）完全不变、不受影响。变的是世界不再整体常驻：地表按**区块**（默认 128×128 格，`CELL_SIZE`/`CHUNK_SIZE` 的公倍数，远大于视口给流式加载留缓冲）为粒度流式生成、按需常驻（默认上限 256 个区块-层，LRU 淘汰）。**区块坐标不是第二套坐标系**——是世界瓦片坐标除以区块边长的纯函数派生，用同一个 `TorusPos` 类型喂给不同粒度的 `TorusSize` 即得，不新增类型、不需要维护第二个真相源。上面「适用范围」段落里「进入具体区域后的分区场景是有界局部地图……锚点使用环面坐标」正是这个模型的雏形——这次工作把它从一句提示扩展成完整的接口形状：`Space` 枚举区分地表 `Surface` 与建筑内部/地下城/洞窟等 `Interior`（各自独立生成的有界不环绕局部图，用一个持久锚点 `TorusPos` 挂在地表某一格，内部规模与地表占地面积无关），并首次规划了 Z 轴／楼层（`Interior.floor`，有顶有底、不环绕，与区块坐标本身仍构成环面是两条不同的规则）。完整论证、被否决方案（区块是否与既有存储块合并等）、内存与性能核算见设计文档。
>
> **对已有实现的影响（如实评估，不是加一个字段量级）**：`ll_world::state::WorldState`、`ll_world::chunk::ChunkGrid`、`ll_world::generate::generate_terrain`（改的是调用方式，`terrain_at_coord`/`build_noise` 核心算法不用动）需要重写；`ll_world::fov::compute_fov`、`ll_render::camera::Camera` 算法本身可以直接复用，但需要为 `Interior` 补一个非环绕的姊妹类型；`ll_core::torus`、`ll_world::noise`、`ll_world::light`、`ll_render::sprite`（精灵绘制层，与本节的 Z/`Space` 是两个不同概念，命名巧合勿混淆）完全不受影响。**这项重写必须在 P5 冻结存档格式之前完成结构定案**（数值——区块边长、常驻上限等——可以之后再调），详见 §15 P5、P7 两行。

- **`ll-core` 必须提供环面坐标类型**，封装距离、方向、插值。环面上两点距离取四种绕法的最小值。
  **禁止在任何地方手写欧氏距离**——遗漏一处就会产生「小地图上很近但寻路绕半个世界」这类极难定位的缺陷。此项由 CI 静态检查强制。
- **地形生成使用可平铺整数噪声**：格点索引对世界周期取模，使 `x = 0` 与 `x = 周期 × 格子尺寸` 命中同一格点。接缝处**构造上连续**，无需任何拼接修补，且**全程整数**。
  > 原方案为「4D 噪声投影 `(x,y) → (cos u, sin u, cos v, sin v)`」。P2 实施时改为模格点：4D 投影需要 `sin`/`cos`，而 IEEE 754 不规定超越函数的精度、不同 libm 实现结果不同，反倒会引入跨平台不确定性。模格点方案无此问题。完整论证见 `crates/ll-world/src/noise.rs` 的模块文档。
- **跨接缝绘制不画副本**：用环面最短带符号位移换算屏幕坐标，绕接缝的情形已被位移计算本身吸收，每个目标仍只画一次。
  > 原方案为「精灵批处理支持最多 4 份偏移副本」。P1 实施时发现不必要：`TorusSize::delta` 返回的已是最短位移，多副本方案既慢又容易出边界错误。
- **气候为周期性条带**：两条赤道 + 两条极圈。玩家持续向北将穿越极地后重新进入热带。此设定纳入世界观——「迷途大陆」即一片没有边缘、首尾相接的土地。

### 7.2 时钟、昼夜与四季

**唯一的世界时钟**是所有时间的真相源。昼夜与季节均由它派生。

> **裁定 P3-5（2026-08-17）**：季节是**时钟的纯函数**，不是时间轴事件，也不存储「当前季节」状态。理由：若季节是事件驱动的状态，就存在一个可与时钟脱节的真相源——本项目已在白昼判定上栽过一次（见 ADR 0010，两处定义每天有 4 小时结论相反）。同时，约束 C4 要求后台世界能推进到任意确定 tick，若季节靠事件驱动，跳进 100 年需补发数百次事件，漏一次即永久错位。
>
> 「季节影响生产速率」不需要事件即可实现：生产速率直接写作 `f(season(tick), …)`，用时现算，不存在「季节变了但速率没跟上」的状态。mod 需要「季节切换」钩子时，由推进过程比较 `season(A) != season(B)` **派生出通知**——通知不是状态，不会脱节。
>

### 7.3 地形与视野

瓦片地形携带通行性、遮挡、光照透过率等属性。FOV 采用对称阴影投射，必须使用环面坐标。

## 8. 时间轴调度器：一套代码，三个尺度

同一个优先队列实现被复用于三个时间尺度，这是选择「时间轴事件队列」而非能量累积制的主要收益：

| 尺度 | 刻度 | 事件示例 |
|---|---|---|
| 战斗 | 行动 | 「3 号角色出手」 |
| 世界 | 小时 / 天 | 「商队 3 天后抵达 X 城」「秋收在 40 天后」「冬季在 12 天后开始」 |
| 经济 | 天 | 「商人甲结束休整，做下一次进货决策」 |

行动耗时 = 基础代价 × 100 / 敏捷。敏捷高的角色自然在同一时间窗内获得更多行动机会，「连动几次」是该公式的自然结果而非特例逻辑。

## 9. 智能体经济与人口

### 9.1 三档 LOD

| 层级 | 范围 | 粒度 | 推进 |
|---|---|---|---|
| 近景 | 玩家当前场景 | 完整瓦片级：位置、FOV、行为树、时间轴 | 按行动 |
| 中景 | 相邻区域、常访区域 | 聚合量 + 具名个体 | 按小时 |
| 远景 | 遥远 / 未访问区域 | 仅 Cohort，粗时间步（周） | 惰性追赶 |

### 9.2 四条可行性约束

- **E1 事件驱动而非 tick 驱动** — 智能体自行决定下一次决策时刻并插入世界时间轴，决策间休眠。单个商人年均约 50 次决策事件；一万智能体约 50 万事件/年，对优先队列压力可忽略。
- **E2 薄个体 + 厚群体** — 每个 NPC 持有持久身份（ID、姓名、职业、家庭、住址、关系值、财产，约 64 字节；两万人约 1.3 MB，压缩后存档无压力）。**决策按 Cohort 批量计算**，同城同职业者共享行为规则，结果按个体特质偏移分摊。仅具名 NPC、商人及玩家视野内个体做独立决策。玩家靠近时 Cohort 解压为个体，离开时压回，身份始终保留。
- **E3 远景降级 + 追溯生成** — 远景仅跑 Cohort 统计，个体决策暂停。玩家返回时缺失的个体历史按 Cohort 均值加个体特质反推补齐。
- **E4 每实体确定性 RNG** — 见约束 C3。

### 9.3 经济模型纪律

- 城镇为市场节点，商队为连接边。价格由本地供需决定。玩家买卖直接改变本地库存并立即反映到价格。
- **强反馈环只允许出现在事件点**（收成日、战争、瘟疫、季节更替）。事件之间保持线性，惰性追赶只需在事件点处分段。
- **必须内置稳定器**：价格软上下限、货币回收汇（税收、损耗、维修）。智能体经济历史上极易出现恶性通胀或通缩死亡螺旋。
- **`tools/ll-econsim` 是必需品而非附加项**——没有它无法判断经济是否收敛。它空跑 100 年世界演进，输出物价、货币总量、人口、库存曲线并检查发散。

## 10. 脚本层与 Mod 框架

### 10.1 Steel 沙箱能力（已实测，`steel-core` 0.8.2）

| 项目 | 实测结论 |
|---|---|
| 死循环中断 | ✅ 305ms 掐断，返回 `Err`，不 panic。中断粒度精确到单条字节码 |
| 中断后复用 | ✅ 同一引擎可继续使用，「一键重载」成本低 |
| 看门狗开销 | ✅ 实测 0.96x，**零开销**，可每帧大量调用 |
| Rust 注册函数的参数检查 | ✅ 缺参 / 多参均报 `ArityMismatch` |
| 深递归 | ⚠️ 调用栈在堆上，不击穿原生栈（1000 万层耗时 644ms 正常返回），**风险是内存而非栈溢出** |
| 内存守卫 | ❌ **原生缺失** |

`InterruptHandler` 位于 `steel::steel_vm::interrupt`，**无 feature 门控**，默认可用。`Engine::run` 要求 `'static` 输入，脚本从文件读入天然满足。

**注意**：Steel 具名函数的参数检查较宽松——缺失参数成为未绑定标识符，仅在实际引用时报错；多余参数被静默忽略。但**所有游戏 API 均为 Rust 侧注册函数，具备严格 arity 检查**，故 mod 与引擎的接口边界是安全的。宽松仅存在于 mod 内部自有函数之间，由 `tools/ll-datacheck` 静态检查兜底。

### 10.2 四道防线

1. **错误捕获** — 每次脚本调用包裹错误边界，返回 `Err` 而非 panic。
2. **降级而非崩溃** — 脚本失败时使用默认行为（伤害算不出记 0，AI 算不出则原地等待），游戏继续运行，错误进控制台。
3. **执行预算** — 时间维度由 `InterruptHandler` 覆盖；**内存维度需自研 `#[global_allocator]` 包装器**，以原子计数器统计脚本执行期间的分配量，超阈值时调用同一个 `ThreadStateController::interrupt()`。复用现成中断通道，开销为每次 alloc/dealloc 一次原子加减。
4. **加载分阶段隔离** — 单个 mod 加载失败不影响其他 mod，除非存在依赖关系。

### 10.3 玩法层内容注册 API 一致性（ADR 0018）

> **规格修订（2026-08-18，裁定见 [ADR 0018](../../../knowledge/decisions/0018-engine-layer-vs-gameplay-layer-scripting-boundary.md)）**：本节原文「本体不享有任何特权通道」没有限定适用范围——字面读法会把渲染、物理、寻路这些显然不该脚本化的系统也卷进「必须能被 mod API 表达」的要求里，这条原则因此要么被字面执行（荒谬），要么被含糊执行（那条线到底在哪，没人说得清）。本次修订按**系统类型**划一条线，取代原文隐含的「本体身份 vs mod 身份」这条轴：
>
> - **引擎层**——渲染、物理、寻路、网络同步、时间轴调度（队列机制本身）、FOV、光照计算——永远是原生 Rust，不进脚本层，本体与 mod 都碰不到。这类系统只有工程正确性，没有「设计者可以选另一种规则」这个自由度，不适用本节的检验。
> - **玩法层**——AI 行为、物品效果、事件响应、任务逻辑、技能效果——本体内容与 mod 用同一套 API，下方原文的检验价值在这个范围内原样成立，只是范围从「一切」收窄为「玩法层」。
>
> 可操作的归类判据（三步法）、逐项验证（含已解决的 `TerrainKind` 迁入注册表、部分解决的 `opens_into` 声明化，以及 [ADR 0016](../../../knowledge/decisions/0016-mod-performance-tiers-by-declaration.md) 守门规则相应收窄的说明），见 ADR 0018，不在此重复。

玩法层内容——职业、技能、物品、怪物、地图生成规则、任务图、行为树、本地化——**本体与 mod 走同一套注册表 API**；引擎层内容（渲染、物理、寻路、FOV、光照、时间轴机制）本体与 mod 都不暴露——不暴露不是缺陷。

这是保证「玩法层 API 覆盖所有内容」的唯一可靠手段：API 存在缺口时，本体自身先无法实现，缺口当场暴露。

### 10.4 命名空间 ID

- 外部形态为字符串：`lostland:fireball`、`yourmod:super_fireball`。装载时统一映射为紧凑整数索引供运行时使用。外部用字符串保证不冲突，内部用整数保证性能。
- **存档必须持久化字符串 ID**（或在存档头保存「索引 ↔ 字符串」映射表）。否则玩家调整 mod 加载顺序后索引全部错位。
- 存档头额外记录当时启用的 mod 列表与版本；缺失 mod 时给出明确提示，不得崩溃。

### 10.5 行为树

行为树定义直接书写为 Steel `.scm`——**S 表达式本身即树结构**，无需发明第三种格式，也无需编写树解析器。Rust 侧仅实现 tick 求值器，节点判断与动作以 Steel 函数实现。

```scheme
(selector
  (sequence (hp-below? 0.3) (flee-from-nearest-enemy))
  (sequence (has-order? 'guard) (attack-anyone-near (order-target)))
  (follow-leader 3))
```

行为树的输出即 `Intent`，因此随从、敌人、召唤物与玩家**共用完全同一条管线**，无特殊分支。随从与敌人的唯一差异是黑板上多一条「玩家下达的当前指令」。

**玩家下达的战术指令与据点派工是同一机制的两个时间尺度**（秒级 / 天级），共用「指令 → 黑板 → 行为树」结构，不是两套系统。

行为树运行时状态（当前节点、黑板内容）依约束 C1 存放于 `WorldState`。

### 10.6 加载管理界面

即 mod 管理器与脚本错误控制台的合体：

- 加载按阶段推进：发现 → 解析清单 → 依赖拓扑排序 → 加载脚本 → 注册内容 → 交叉引用校验
- 结果分组显示：已加载 / 有警告 / 失败；可展开查看含文件名与行号的详细错误
- 支持单个 mod 一键重载
- 开发期挂载文件监听，`.scm` 存盘即生效

## 11. 数据、存档与本地化

### 11.1 格式分工

| 类别 | 格式 | 理由 |
|---|---|---|
| 用户设置 | TOML | 支持注释，玩家可手改 |
| 游戏数据表 | Steel `.scm` | 数据与效果逻辑同文件，避免两处维护脱节 |
| 资产元数据 | JSON 源 → 打包为二进制 | 编辑期 diff 友好，运行期不解析文本 |
| 本地化文本 | Fluent `.ftl` | 处理复数、变量插值、语言回退 |

### 11.2 存档

- **头部**：明文 JSON。schema 版本、存档时间、角色名、当前区域、游玩时长、启用 mod 列表、ID 映射表。存档列表界面仅读此部分。
- **主体**：`serde` + `postcard` + `lz4_flex`。
- **迁移**：头部 schema 版本驱动迁移函数链，旧档逐版本升级。
- **双模式**：模式2（永久死亡）仅保留断点续玩存档；模式3（自由读档）支持多存档位。**模式2 → 模式3 单向降级，不可逆**，降级动作写入头部并永久标记。

### 11.3 i18n

- **代码中不得出现任何硬编码的用户可见字符串**，由 CI 检查强制。
- 字体思源黑体 Source Han Sans（Adobe 发行版，OFL-1.1），Regular + Bold 两档字重打包（约 16MB），CJK 与拉丁字形出自同一套设计系统。**文本渲染独立于 640×360 世界层的整数缩放管线，走原生分辨率栅格化**——像素点阵字体在低分辨率下小字号糊连、且不带真实字体度量，撑不住变宽排版与 CJK 断行判定，故不采用（原方案 Fusion Pixel Font 已废弃，见 §3 表下方修订说明）。排版由 `cosmic-text` 处理整形、断行、字形回退，`glyphon` 负责把排版结果渲染到 wgpu。
- 首发简中 + 英文，日语建空包。双语并行开发以尽早暴露硬编码字符串与长文本下的 UI 排版溢出。

## 12. UI 双轨

- **游戏内 UI（`ll-ui`）自研**：九宫格切片边框 + 位图字体 + 焦点导航（键盘方向键 / 手柄摇杆直接可用）。现成 UI 库外观为现代扁平风，与像素美术不兼容，且为鼠标设计，手柄导航体验差。菜单是玩家高频接触的界面，值得自研。
- **工具链 UI（`tools/`）使用 `egui`**：工具不需要美术风格，需要的是开发速度。

游戏内菜单需覆盖：主菜单、暂停菜单、设置（画质 / 分辨率 / 整数缩放倍率 / 音量 / 按键重绑定 / 语言切换）、存档管理、加载管理界面。

### 12.1 精灵尺寸解耦

瓦片网格恒定 16×16，但**精灵的「逻辑占地格数 footprint」与「视觉尺寸 + 锚点 pivot」必须是两个独立概念**，并配合 Y 轴排序解决高精灵遮挡。

普通单位 16×24 占 1 格；重点目标（Boss、精英、关键 NPC）32×48 占 2×2 格。

**此项为 P1 渲染层的硬性接口约束，不得延后**——后期补入将推翻整个精灵批处理布局。

## 13. 编码规约

- **模块化优先**：文件 200–400 行为宜，800 行为上限。按功能域组织，不按类型组织。
- **注释**：所有公开项必须有文档注释说明「做什么、怎么用、依赖什么」。注释解释**为什么**，而非复述代码在做什么。
- **函数式优先**：非性能热点一律采用不可变数据与纯函数。性能热点经 profiler 确认后方可引入可变优化，并须注释说明原因与实测数据。
- **不可变性**：默认返回新值而非原地修改。`apply` 是唯一的例外，且其修改被严格限制在无逻辑的赋值上。
- **错误处理**：显式处理，不得静默吞掉。面向用户的错误须可读，日志侧记录完整上下文。
- **代码卫生（持续执行）**：删除无用代码文件、清理过时文档、移除死代码。CI 挂载死代码检测；文档与代码不一致即视为缺陷。本规格文档本身也须随决策变更同步更新。

## 14. 质量保障（QA）

测试不是各 crate 各自为政的附属品，而是与实现同等的交付物。本节定义**全项目统一的测试分层**，每个阶段的实施计划必须逐层落实。

### 14.1 测试分层

自下而上，数量递减、单次耗时递增。**下层不到位就往上层堆测试，是最常见也最昂贵的错误。**

| 层 | 类型 | 手段 | 覆盖对象 |
|---|---|---|---|
| L1 | **单元测试（白箱）** | `#[cfg(test)]` 内联模块 | 私有函数、分支、边界条件。可见内部实现 |
| L2 | **属性测试** | `proptest` | 不变量而非具体用例。见 §14.2 |
| L3 | **集成测试（黑箱）** | `tests/` 目录，仅用公开 API | crate 对外契约。**看不到内部实现**，故能发现「改了内部就崩」的脆弱设计 |
| L4 | **快照测试** | `insta` | 地图生成结果、UI 布局、序列化产物、错误信息文案 |
| L5 | **模糊测试** | `cargo-fuzz` | 一切解析外部数据的入口。见 §14.3 |
| L6 | **端到端测试** | 无头模式 + 脚本化输入序列 | 完整游戏循环 |
| L7 | **视觉回归** | 离屏渲染 → 基准 PNG 容差比对 | 渲染管线、精灵批处理、UI 绘制 |
| L8 | **性能基准** | `criterion` | 防性能回归。见 §14.4 |

所有测试工具均为 MIT / Apache-2.0，符合 §3 许可证约束。

### 14.2 属性测试的重点对象

具体用例只能证明「这一个输入是对的」，属性测试证明「所有输入都满足某不变量」。本项目有几处天然适合：

| 对象 | 待验证的不变量 |
|---|---|
| 环面坐标 | 距离对称（`d(a,b) == d(b,a)`）、三角不等式、距离恒 ≤ 世界尺寸的一半、平移不变性 |
| 存档 | **序列化往返恒等**：`deserialize(serialize(w)) == w`，对任意随机生成的 `WorldState` |
| 时间轴调度器 | 弹出顺序恒按时刻单调不减；同刻事件的相对顺序稳定（决定性） |
| Effect 应用 | 同一批 `Effect` 无论以何种顺序累积，`apply` 后的世界哈希一致（若不成立，说明存在顺序依赖，必须显式排序） |
| 命名空间 ID | 字符串 ↔ 整数索引映射双向恒等 |
| 可平铺整数噪声 | 接缝处连续：`terrain(0, y) == terrain(W, y)`，对任意 `y` |

### 14.3 模糊测试的必测入口

凡是**读取外部数据**的地方都是攻击面，必须 fuzz——玩家会拿到损坏的存档、第三方 mod 会写出畸形清单：

- 存档反序列化（含被截断、被篡改的字节流）
- mod 清单解析
- 资产元数据与图集 JSON 解析
- Steel 脚本加载路径
- 本地化 `.ftl` 解析

**判定标准**：任何输入都不得 panic、不得 OOM、不得无限循环。只允许返回 `Err`。

### 14.4 关键专项测试

- **确定性回归（最高优先级）** — 固定种子 + 固定 Intent 流，断言 `WorldState` 哈希逐帧稳定。这是防止约束 C3 / C4 / C5 被破坏的**唯一有效手段**，且必须在 P0 就搭好框架，否则等到 P9 才发现世界会分叉就来不及了。
- **跨平台一致性** — 同一种子在 Windows 与 Linux 上必须产出**逐位相同**的世界哈希。浮点差异会摧毁确定性，因此涉及世界状态的计算须使用定点数或严格约束的浮点运算。CI 双平台矩阵对比哈希。
- **经济收敛** — `ll-econsim` 空跑 100 年，断言物价、货币总量、人口不发散。
- **脚本沙箱** — 死循环、无限分配、深递归、畸形语法各一例，断言均返回 `Err` 且进程存活。
- **大量实体压力** — 逐级加压至目标实体数，记录帧时间曲线，防止 O(n²) 悄悄溜进来。

### 14.5 覆盖率与测试有效性

- 行覆盖率 ≥ **80%**（`cargo-llvm-cov`），核心 crate（`ll-core`、`ll-sim`、`ll-world`）≥ **90%**。
- **覆盖率不等于测试有效性**。高覆盖率完全可能来自「调用了但没断言」的空转测试。因此额外引入**变异测试**（`cargo-mutants`）：自动篡改代码，检查是否有测试因此失败。存活的变异体即测试盲区。核心 crate 的变异存活率须 < 20%。

### 14.6 测试自身的质量要求

- 采用 **AAA 结构**（Arrange–Act–Assert），三段之间空行分隔。
- 测试名描述**行为**而非函数名：`环面距离在跨越东西接缝时取较短一侧` 优于 `test_distance`。
- **一个测试只断言一件事**。断言堆叠会让失败信息无法定位。
- **禁止测试实现细节**。断言公开行为，否则重构必然连带大批测试红灯，久而久之测试会被当成负担删掉。
- 测试必须相互隔离，不依赖执行顺序，不共享可变全局状态。

### 14.7 CI 门禁

合并到 `main` 前必须全部通过，**任一项失败即阻断**：

| 门禁 | 工具 |
|---|---|
| 编译无警告 | `cargo clippy -- -D warnings` |
| 格式统一 | `cargo fmt --check` |
| 全部测试通过 | `cargo test --workspace` |
| 覆盖率达标 | `cargo-llvm-cov` |
| 许可证合规 | `cargo-deny` |
| 无硬编码用户可见字符串 | 自研检查（§11.3） |
| 无手写欧氏距离 | 自研检查（§7.1） |
| 无死代码与过时文档 | 自研检查（§13） |
| 跨平台世界哈希一致 | Windows + Linux 双平台矩阵 |

变异测试与模糊测试因耗时较长，按夜间定时任务执行，不阻断单次合并。

### 并行切分

Crate 边界即任务边界。P0 完成后，`ll-render`、`ll-audio` 两条线互不依赖，可完全并行。`ll-world` 与 `ll-sim` 需串行于 `ll-core` 之后。工具链在对应数据格式冻结后即可并行启动。

> **修正（2026-08-18）**：原文把 `ll-text` 也列进这条互不依赖的并行线，P4 实现后核实这不准确——`ll-text` 需要 `ll-render::GpuContext` 才能把排版结果栅格化到 wgpu（见 §5「实现进度核实」），必须在 `ll-render` 之后才能开工。这次没有造成实际问题，因为 `ll-render` 早在 P1 就已交付，`ll-text` 在 P4 才开工时依赖已经满足；但若后续阶段还想按「crate 边界即并行边界」的原则规划新任务，应先核实一遍真实的 `Cargo.toml` 依赖，不能只看 §5 分层图的分组呈现（同一层级的编排并不保证真的互不依赖）。

## 17. 风险登记

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 智能体经济不收敛 | **高** | 事件点分段 + 稳定器 + `ll-econsim` 持续压测。这是全项目最大风险 |
| 跨平台浮点差异摧毁确定性 | **高** | 世界状态相关计算使用定点数或严格约束浮点；CI 双平台矩阵比对世界哈希（§14.4）。**必须在 P0 定型数值类型**，后期更换等于重写 |
| 逐层铺地基导致长期无可见产出 | 中 | 每阶段强制交付 `examples/` demo |
| 环面坐标遗漏导致隐蔽缺陷 | 中 | 类型封装 + CI 静态检查禁止手写欧氏距离 |
| 脚本内存失控 | 中 | 自研 `#[global_allocator]` 守卫（P4 交付） |
| Mod API 覆盖不全 | 中 | 玩法层内容本体与 mod 走同一套注册 API（§10.3，ADR 0018），缺口在本体自身实现时当场暴露 |
| 混合精灵尺寸后期返工 | 中 | footprint / pivot 解耦作为 P1 硬性接口约束 |
| 依赖引入非宽松许可 | 低 | `cargo-deny` CI 门禁 |
