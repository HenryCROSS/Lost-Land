## 一、第一组：L0–L5（主体，不裁）

### L0 提交那一刻取整

**算法一份**：`widget/geometry.rs` 新增

```rust
pub fn snap(&self) -> Rect   // 取整**边界**，不是取整 (origin, size)
```

实现取 `x.round()` / `y.round()` / `right().round()` / `bottom().round()`，宽高
由取整后的边界相减得出。**这一条是「相邻两块不留缝也不重叠」的全部理由**：
两块相邻矩形共享的那个边界值是同一个 `f32`，`round()` 是函数，同一个输入必然
给出同一个输出。若改成分别取整 `x` 与 `width`，`round(x)+round(w)` 与
`round(x+w)` 在半像素上就会差一格——那才是缝。

**落点分两层，不是两份真相源**（两层调的都是 `Rect::snap`，且取整幂等）：

1. **积木自身**：`widget/panel.rs` 的 `panel_quads` / `textured_panel_quads`
   对九块各 `snap()` 一次；`widget/list.rs` 的 `RowCursor::push` 对
   `Label` 原点取整（**内部游标 `cursor_y` 不取整**——累计推进保持精确，
   只有提交出去的那一份取整，否则误差会逐行累积）。
   这一层满足规格 6.1 写死的那条判据。
2. **提交那一刻**：`widget/layer.rs` 新增 `LayeredFrame::snap_to_pixels()`，
   在 `build_hud_frame` 与 `build_screen_frame` 的 `return` 之前各调一次。

**为什么要第 2 层**：进 `QuadInstance` 的矩形不止面板——条形（`bar.rs`，
`width * fraction` 是半像素的最大来源）、昼夜滑条与指针、世界地图的每一格、
模态屏背板与行高亮、地图上的玩家标记，共 20 多处 `QuadInstance { … }` 字面量。
逐处改是 20 处**手写清单**，而本仓库已经证明手写清单会漏（`layout.rs` 的地形
清单漏掉沙漠与冻原，从落地起在盲区里直到批次 28）。放在帧的出口上，**新加的
任何一块 quad 自动被覆盖**，漏不掉。

**判据**（新增测试，`hud/render.rs` 与 `screen/mod.rs` 各一条，外加 `panel.rs`
一条）：
- `panel_quads` 对非整数 `Rect` 产出的九块，`x`/`y`/`right()`/`bottom()` 全部
  `fract() == 0.0`；且四角右边界 == 边块左边界（无缝无叠）。
- 用**故意带半像素的屏幕尺寸**（`1281.5 × 719.5`）跑 `build_hud_frame` /
  `build_screen_frame`，遍历**全部四层**的 `quads` + `textured_quads` + `labels`，
  每一个的边界/原点都是整数。**先断言这一帧真的非空**（否则「零个元素全部满足」
  恒绿——本会话点名的第二个假绿形状）。

**不做**：不取整 `screen_row_rects`/`world_map_rect` 的反算路径以外的东西；
`ScreenGeometry` 的 `panel` 与 `row_rects` 跟着取整（点击落在第几行与高亮画在
哪儿必须仍然是同一份），这是本条唯一一处越出「提交那一刻」的取整，理由写在
第八节。

### L1 三个区 + 中段留白

`ScreenZone` 落在 `widget/zone.rs`，三个变体 `Resident` / `Floating` / `Modal`，
并提供 `ScreenZone::of(UiLayer) -> ScreenZone`。**它是 `UiLayer` 的派生值，不是
第二个字段**——「新面板必须声明属于哪个区」这件事因此不需要任何新的接线：选层
本来就是强制的，选了层就选了区。`UiLayer::Modal` 是 N9 的事，本批不加；今天
`Modal` 区没有成员，`of()` 里把这件事写清楚。

**中段留白的判据要比规格原文多一个例外**：规格写「所有 `Hud` 层矩形要么
`right() <= 屏宽/2` 要么 `x >= 屏宽/2`」。批次 23 的按键提示行（`Hud` 层、
水平居中、贴下沿，620 宽）**照这条会红**——而它是对的：留白规则的理由原文是
「那是玩家看世界的地方」，屏幕最下沿那一条窄边不是。因此判据改成三选一：

> 左半 / 右半 / **底栏**（`y >= 屏高 - BOTTOM_STRIP_HEIGHT`）

`BOTTOM_STRIP_HEIGHT` 由 `bottom_rows` 从它自己的常量导出（= 反馈行的下沿偏移），
**不在测试里抄一个数**。测试在 1280×720 与 1920×1080 两个尺寸下各跑一遍。

### L2 一个锚点函数 + 防第五份（本批重点）

**函数**（`widget/geometry.rs`）：

```rust
pub enum Anchor { TopLeft, TopRight, TopCenter, Center, BottomCenter }
impl Rect { pub fn anchored(screen: (f32,f32), anchor: Anchor, size: (f32,f32), margin: f32) -> Rect }
```

`Center` 忽略 `margin`（居中没有边距可言），文档里写明。**一律不钳制**——今天
四处里有一处（`bottom_row_panel` 的 `.max(0.0)`）钳、三处不钳，三处都没说为什么。
统一取「不钳」，与 `equipment_origin_x` / `placed_action_menu` / `centered_origin`
三处**已经写下理由**的那一侧一致（钳制会把「窗口配置改小了却没人发现面板被塞没
了」掩盖成一块看起来正常的面板）。反馈行那一处的 `.max(0.0)` 因此消失，这是本条
唯一一处**行为**变化，只在屏幕比面板还矮时可观察。

**五份副本改写后的落点**（每处都留一条「改写前后逐像素相同」的回归断言，
用改写前的原算术表达式作为期望值写在测试里）：

| # | 今天 | 改成 |
|---|---|---|
| 1 | `equipment_origin_x`：`w - EQUIPMENT_RIGHT_MARGIN - EQUIPMENT_WIDTH` | `TopRight`，margin = `SCREEN_MARGIN` |
| 2 | `placed_action_menu` 水平：`(w - ACTION_MENU_WIDTH) * 0.5`，`top = SCREEN_MARGIN + PANEL_GAP` | `TopCenter`，margin = `ACTION_MENU_TOP_MARGIN` |
| 3 | `placed_action_menu` 垂直（`ScreenCenter` 分支）：`(h - height) * 0.5` 再整体平移 | `Center` |
| 4 | `bottom_row_panel`：`(w - width) * 0.5`, `(h - offset).max(0.0)` | `BottomCenter` |
| 5 | `centered_origin`（模态屏）：`(w - pw)/2, (h - ph)/2` | `Center` |

`world_map_rect` 顺带也改成 `Center`（尺寸仍按 10% 比例现算）——它今天写的是
`Rect::new(margin_x, margin_y, w-2m, h-2m)`，与「居中一块」是同一件事的另一种
写法。改过去之后，`ll-game` 那一侧的反算（`world_map_zone_at_pixel`）与画图共用
的仍然是同一个 `world_map_rect`，不受影响。

**防第五份的判据（所有者点名要的那一条）**

形态照抄仓库既有先例 `scripts/ci/check_no_manual_euclidean_distance.sh`——那道
门禁做的正是同一件事（禁手写公式、逼人用共享的那个），本批不发明新范式。

新增 `scripts/ci/check_single_anchor_impl.sh`，扫 `crates/ll-ui/src`、
`crates/ll-game/src`，**除 `crates/ll-ui/src/widget/geometry.rs` 外**任何一行命中
以下四种形状即红：

1. `(screen_width - …) * 0.5` / `(… ) / 2.0` —— 水平居中
2. `(screen_height - …) * 0.5` / `(… ) / 2.0` —— 垂直居中
3. `screen_width - … - …`（**两次**减法）—— 贴右
4. `screen_height - … - …` —— 贴下

标识符按 `screen_width|screen_height|屏宽|屏高|window_width|window_height` 匹配。
`//` 开头的注释行跳过（与欧氏距离那道门禁逐字同一条豁免）。

**为什么是「两次减法」而不是一次**：`world_map_rect` 里的
`screen_width - margin_x * 2.0` 是**算尺寸**不是**算位置**，一次减法；贴边定位
必然是「屏宽 − 边距 − 自身宽」两次。这条区分让门禁不误伤尺寸计算，也不留下
「加进某张清单就能消红」的口子——**没有清单**，唯一的消红方式是调用
`Rect::anchored`。

**它拦不住什么，如实写在脚本头**：有人先算 `let half = w * 0.5;` 再自己减，
门禁看不见。所以本条**不是单点防线**：L1 的中段留白断言与 L0 的整帧取整断言都
是**行为**判据，跑在 `build_hud_frame` 的产出上，新面板绕开 `anchored` 手写落位
仍然会在那两条上显形。三条一起才是「防第五份」。

**反例验证（点名的第 ①）**：在 `hud/render.rs` 里真的写一份第五份居中实现，
跑门禁，确认它红、且红在那一行；再确认**红的原因是形状 1**（脚本逐条打印命中的
是哪一种形状，不是只报「有违规」）。

### L3 间距刻度收敛

**新模块 `widget/metrics.rs`**，装三个常量：`SCREEN_MARGIN = 16`、
`PANEL_GAP = 10`、`PANEL_PADDING = 6`。放在 `widget/` 是因为 `hud` 与 `screen`
都依赖 `widget`、彼此不依赖——规格 3.2 抱怨的「两套常量互不知情」的根子就是
没有一个双方都看得见的地方。`hud::render::{SCREEN_MARGIN, PANEL_GAP}`、
`hud::DEFAULT_PADDING`、`screen::SCREEN_PADDING`、`screen::SCREEN_SIDE_MARGIN`
全部改成 `pub use` 重导出，**公开路径一个都不断**（`ll-game` 与两道门禁在用）。

`PANEL_PADDING` 取 **6**（HUD 那一档），不取 10。规格只说「合并」没说取哪个值，
理由写在第八节。

顺带清掉的裸字面量：
- 经验条那处 `stack_below(4.0, …)` → `PANEL_GAP`（**面板下移 6px**）
- `bottom_rows::BOTTOM_MARGIN = 16.0` → `SCREEN_MARGIN`
- `bottom_rows` 两行之间的间隔今天是 `DEFAULT_PADDING`（内边距当间隔用）→
  `PANEL_GAP`（**反馈行上移 4px**）
- `placement.rs` 的 `SCREEN_MARGIN + PANEL_GAP` → 具名 `ACTION_MENU_TOP_MARGIN`

`WORLD_MAP_CAPTION_MARGIN = 8.0` **保留**：它已具名，且文档写明「刻意比
`SCREEN_MARGIN` 小，否则会压到第一行格子」——L3 判据要的是「不再出现**未命名**
的像素字面量」，不是「只许两个值」。

### L4 参数错位

`bar_rect.stack_below(PANEL_GAP, INVENTORY_WIDTH).origin()` → 直接写
`(bar_rect.x, bar_rect.bottom() + PANEL_GAP)`。取规格给的第一个选项（显式构造），
不上 newtype：给 `f32` 尺寸上 newtype 会波及 `Rect` 全部方法与全 crate 调用点，
那不是本批的面积。逐像素零变更。

### L5 状态栏与昼夜条对齐

今天 `RESOURCE_BAR_WIDTH = 300` ⇒ 昼夜条 `300*2+10 = 610`，状态栏 620。改法取
**`RESOURCE_BAR_WIDTH = (STATUS_WIDTH - PANEL_GAP) / 2.0 = 305`**，昼夜条随之
= `STATUS_WIDTH`。这样三者（状态栏 / 两条资源条并排 / 昼夜条）右边界**全部**
对齐；若反过来把昼夜条硬改成 620，它就与它正上方那两条资源条不齐了——那是拆东墙
补西墙。

**判据**：`status_panel.rect.right() == day_night_rect.right()` 且
`== mana_rect.right()`。**规格说这条今天会红，落地前先跑一遍确认**。

## 八、规格没裁定、本批临时选的做法（滚动记录，收工搬进最终报告）

1. **L0 取整分两层**（积木自身 + 帧出口），规格只写了积木那一层。理由：规格
   6.1 的规则原文说的是「每一个进入 `QuadInstance` 的矩形」，而它给的三个落点
   只覆盖面板与文本，覆盖不到条形/地图/背板那二十多处。
2. **`Rect::snap` 取整边界而不是取整 `(origin, size)`**。规格只写 `round()`，
   没说 round 什么。
3. **`ScreenGeometry` 的 `panel` 与 `row_rects` 也取整**——这一处越出了「提交
   那一刻」，理由是点击命中用的是 `row_rects`、高亮画的是同一批矩形，两者取整
   与否必须一致，否则会退化成「偶尔点到隔壁那行」。
4. **L1 的中段留白多一个「底栏」例外**，规格原文只有左半/右半两选一。
5. **`ScreenZone` 是 `UiLayer` 的派生值，不是新字段**。规格说「新面板必须声明
   属于哪一个」，没说怎么声明。
6. **`PANEL_PADDING` 取 6 不取 10**。规格只说合并。取 6 是因为它只会让内容宽
   **变宽**，溢出门禁的行数预算不可能因此新超；取 10 会把六块 HUD 面板的内容宽
   各缩 8px，可能连带改动门禁判据，那是把两件事绑在一起。
7. **`bottom_row_panel` 的 `.max(0.0)` 钳制取消**，统一到另外三处「不钳」的那一侧。
8. **L5 改 `RESOURCE_BAR_WIDTH` 而不是改 `DAY_NIGHT_BAR_WIDTH`**（规格只说「对齐」，
   没说谁让谁）。
9. **防第五份的门禁没有豁免清单**。欧氏距离那道门禁也没有；有清单就等于留了
   「加一行就能消红」的口子。
10. **W7 那条「今天会红」的断言本批不写**（见第二节）。规格十二节点名 I8 是反面
    教材、要在落地 W7 时换掉——本批不落地 W7，因此那条字符数断言原样留着，
