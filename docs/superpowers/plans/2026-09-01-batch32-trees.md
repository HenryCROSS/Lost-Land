## 一、所有者的裁定与它的代价

世界 3072×2304 ＝ 7 077 888 格。森林哪怕只占 15% 也是**一百万格以上**。
独立实体存不下也算不动 ⇒ 走 ADR 0009：

```
这一格有没有树、是什么树 = 派生(种子, 位置, 地形, 气候)   ← 零存储，用时现算
```

## 三、派生层

### 3.1 判据

```text
derived_tree_at(seed, pos, kind, forest, world_height, band_width):
    if kind != forest { return None }                       // ① 只有 forest 长树
    if fold(H("presence"), 1000) >= TREE_DENSITY_PERMILLE { return None }  // ② 疏密
    return species_from(fold(H("species"), BAND_WEIGHT_TOTAL), band_at(pos.y))  // ③ 树种

    H(domain) = FNV1a( le64(seed) ‖ le64(pos.x) ‖ le64(pos.y) ‖ len_prefixed(domain) )
    fold(h, n) = ((h as u128 * n as u128) >> 64) as u32      // Lemire 乘法取高位
```

- **`forest` 地形保留当底图**（所有者要求原话）。判据 ① 是一次 `TerrainKind`
  相等比较，O(1)。
- **两个域字符串（`"presence"` / `"species"`）**：同一格的「有没有树」与「是什么树」
  必须互相独立。共用一个摘要再切两段位域会让密度与树种相关（低位雪崩弱那半正是
  批次 28 踩过的坑）。两次哈希各自 24 字节输入，仍是常数时间。
- **混入次序：`seed, x, y, 域名`**——域名（长字符串）**放最后**。
  **这不是风格选择，是批次 28 实测逼出来的**：FNV-1a 逐字节「异或 + 乘质数」，
  最后混进去的那几个字节没有足够轮数被摊开；而 `write_i64` 写的是小端 8 字节，
  世界坐标那种小整数**高 7 字节全是 0**，相邻两格只差最低一个字节，之后只剩
  7 轮「异或 0 再乘」。把 `y` 放最后 ⇒ 纵向条纹（批次 28 实测 32% → 47%）。
  本批**照抄那个已验证的次序**，并**自己再实测一遍**（第十节），不假设它会自动成立。

### 3.2 确定性怎么保证

- **纯函数**：输入只有 `(seed, pos, kind, forest, world_height, band_width)`，
  无状态、无时钟、无 RNG、无哈希容器（C5）。
- **不碰 `DetRng`（C3）**：派生层每帧被调用的次数取决于**这一帧画了几格**
  ——摄像机缩放、窗口大小、视野半径都会改变它。让这种量参与随机流等于把确定性
  重放交给显示器分辨率。批次 28 在同一处的裁定逐字适用。
- 哈希取 `ll_core::hashing::StateHasher`（FNV-1a），模块文档写明「完全由整数运算
  构成、由规范唯一确定，因而跨平台跨版本恒定」。**不新写一个哈希。**

### 3.3 「没有消耗随机流」怎么证（不是推理，要给证据）

1. `crates/ll-world/src/tree.rs` 全文 `grep -c DetRng` = **0**；
2. 三条黄金基准重冻后，**把偏差层那一行哈希混入关掉**，三条精确回到旧值
   （见第九节四步证据的第 ② 步）——若派生层消耗了随机流，关掉偏差层
   **回不到旧值**；
3. 一条断言：同一格连算两次结果相同，且**中间穿插一万次别的格子**的派生调用
   （若有隐藏可变状态/随机流，穿插会改变第二次的结果）。

### 3.4 O(1) 怎么证

- 结构上：两次定长哈希（各 24 字节输入）+ 两次乘法折算 + 一次 `TerrainKind` 比较。
  **没有循环、没有分配、没有查表遍历**。
- 判据上：一条断言，`derived_tree_at` 在世界 4 个数量级不同的高度
  （`world_height` = 64 / 640 / 6400 / 64000）上产出的结果**不依赖于世界规模的遍历**
  ——用「同一 `pos` 在不同 `world_height` 下调用次数恒定」不可测；
  改用**可测的**判据：`ll_world::tree` 不允许出现 `for`/`while`/`iter()`
  （由一条读源码的断言钉住，与仓库既有的 `check_single_anchor_impl.sh` 同一手法）。

  **这条判据的局限如实登记**：它证的是「本函数体内没有循环」，不是「渐近 O(1)」。
  真正的 O(1) 论证是结构性的（上一段），这条断言只防**回潮**（下一个人往里加一个
  「扫周围 8 格」的循环）。

### 3.5 环面

**一行取模都不写。** 入参类型是 `ll_core::torus::TorusPos`：字段私有、只能经
`TorusSize::wrap` 构造，不变式是坐标恒被规范化到 `[0,w) × [0,h)`。
**绕回这件事在类型边界上就已经做完了**——环面上同一个物理格子，无论从哪个方向
走到它，`TorusPos` 都是同一个值，因此派生结果必然相同。

唯一的例外是 `climate::band_at(y, ..)`，它**刻意**接受未环绕的原始 `y`
（见该函数文档）——本批传进去的是 `pos.y()`，已经规范化，落在合法域内。

一条断言钉住环面接缝：`wrap(x, y)` 与 `wrap(x + w, y + h)` 的派生结果相同。

## 四、偏差层

### 4.1 形状

```rust
// crates/ll-world/src/tree.rs
pub enum TreeSpecies { Oak, Pine, Palm }          // 引擎侧枚举，见第五节

pub struct TreeDeviation {
    /// 现在这一格站着什么树；`None` = **被砍掉了**（派生说有、现在没有）。
    pub species: Option<TreeSpecies>,
    /// 最近一次采果的世界时刻；`None` = 从未采过（果子按派生挂着）。
    pub harvested_at: Option<Tick>,
}

pub struct TreeDeviations { by_pos: BTreeMap<TorusPos, TreeDeviation> }
```

- **`BTreeMap` 不是 `HashMap`**（C5）：这份表要参与 `WorldState::hash()` 的遍历，
  哈希容器的桶序会让同一逻辑状态产出不同摘要。`TorusPos` 已派生 `Ord`
  （`crates/ll-core/src/torus.rs:96`）。
- **`species: Option<..>` 而不是另开一个 `Felled` 变体**：「这一格现在站着什么」
  是一个问题，答案要么是某种树要么是没有。两个字段（`felled: bool` + `species`）
  会造出 `felled: true, species: Some(Oak)` 这种无意义组合。
- **一格一条记录**，砍→种→采共用同一条：一格被反复动过不会累积多条。
- `write_hash` 写在 `tree.rs` 自己身上（`FactionTable::write_hash` 的先例），
  **不往 `state.rs` 里堆**——那个文件已经在行数棘轮快照里（2023 行）。

### 4.2 解析层

```rust
pub fn tree_at(world: &WorldState, pos: TorusPos, forest: TerrainKind) -> Option<Tree>
pub struct Tree { pub species: TreeSpecies, pub fruit_ready: bool }
```

偏差**覆盖**派生：查到偏差记录就用它（`species: None` ⇒ 这里没有树，**派生说有也没有**），
查不到才现算。果子：`harvested_at` 为 `None` ⇒ 有果；否则
`world.clock >= harvested_at + FRUIT_REGROW_TICKS` 才重新有果。

### 4.3 存档

- `WorldState::trees` 是**存档主体新字段** ⇒ `CURRENT_SCHEMA_VERSION` **6 → 7**。
  `scripts/ci/check_save_schema_version.py` 会拦，照它的提示做，**不绕过**。
- **字段加在 `WorldState` 与 `WorldStateRepr` 的末尾**：postcard 按声明顺序吃字节，
  加在中间会让后续字段的字节被错位读成**合法值**（静默数据损坏）。
- **不写 `#[serde(default)]`**：postcard 非自描述，它在那条路上是**空操作**
  （见 `check_save_schema_version.py` 头注释里那条实测）。**不写没实测过的兼容性声明。**
- **老存档实测**（要跑，不许推断）：
  1. 一份 schema 6 的老存档读回来会怎样——照批次 3 的两条写法验**具体错误**，
     不是「大概会拒绝」；
  2. 「版本不对就明确拒绝」那三条既有测试仍绿；
  3. 结论如实写进第十节，**不写迁移**（与交接文档第〇之二第 9 条同一条策略）。

### 5.1 分布受什么影响

- **地形**：只有 `forest` 长树（判据 ①）。这一半**是退化的**（只有一种地形长树），
  如实登记，不假装两个轴都在起作用。
- **气候**：`ClimateBand`（`ll_world::climate::band_at`，已落地）决定**树种权重**：

  | 气候带 | Oak | Pine | Palm |
  |---|---|---|---|
  | `Hot`（干热带） | 3 | 0 | 13 |
  | `Temperate`（温带） | 11 | 4 | 1 |
  | `Polar`（极地带） | 2 | 14 | 0 |

  权重和恒为 16（折算基数）。**刻意不是 1:1 硬映射**：硬映射会让「树种受气候影响」
  这条判据退化成「查一次 `match`」，测不出权重表有没有被接上；权重混合让每条带都是
  **可测的比例**，第十节给实测数字。**含 0 权重**（热带无松、极地无棕榈）
  ——那是判据能咬住的地方：把权重表改成全相同，「三条气候带的树种分布互不相同」当场红。

## 六、交互：砍 / 种 / 采

**一个意图变体带一个动作枚举**，不是三个意图（`Intent::Trade { direction }` 的先例）：

```rust
Intent::TendTree { actor: EntityId, pos: (i32, i32), action: TreeAction }
enum TreeAction { Fell, Harvest, Plant }
```

一条 `resolve_tend_tree`，三条动作共用前置闸门 ⇒ 少一份漂移面。

### 6.1 闸门（任何一道不过 = **零效果**，与既有五道闸门同一形状）

共用：① `actor` 存在且活着；② `pos` 够得着（与 `Intent::PickUp` 同一条范围判据，
**不另写一份**）；③ 目标格地形是 `forest`。

| 动作 | 额外闸门 | 效果 |
|---|---|---|
| `Fell` | 那一格现在真的有树 | `SetTreeDeviation{species: None, harvested_at: None}` + 木料进背包 + `ScheduleNext` |
| `Harvest` | 有树 **且** 果子已长好 | `SetTreeDeviation{species: 保持, harvested_at: now}` + 种子进背包 + `ScheduleNext` |
| `Plant` | 那一格现在**没有**树 **且** 背包里有种子 | 消耗一颗种子 + `SetTreeDeviation{species: 该地气候的派生树种, harvested_at: None}` + `ScheduleNext` |

### 6.2 产出（两件新物品，追加在 `items.json5` 末尾）

| id | 从哪来 | 到哪去 |
|---|---|---|
| `lostland:timber`（木料） | 砍伐 | 材料，可堆叠、无耐久 |
| `lostland:tree_seed`（树种） | 采果 | 培植消耗 |

**只有两件，闭环**：采 → 得种 → 种 → 长树 → 砍 → 得木料。
「宁可少而扎实」：三条路全部走通，而不是发明五种果子没人验过。

**树种决定木料产量**（`Oak 3 / Pine 2 / Palm 1`）——这是「多树种」在玩法上
**唯一真实的差异**，也是判据能咬住的地方（把三个数字改成一样，
「不同树种砍出的木料数量不同」当场红）。

**种子不分树种**：种下去长出什么由**那块地的气候**决定，不由种子决定。
这与「分布由气候决定」是同一条规则的两次应用，不是两套逻辑。

### 6.3 结算侧怎么拿到 `forest` 与两个物品索引

新开一条**窄接口** `TreeCatalog`（`forest_kind()` / `timber_def()` / `seed_def()`），
挂进 `ResolveCatalogs`，空实现 `NoTrees` 全返回 `None` ⇒ **不接这一路时树意图零效果**。
这是仓库既有的依赖倒置手法（`SkillCatalog`/`QuestCatalog`/`ContentIdLookup` 同一套），
**不是新发明**，也不给 `resolve_*` 那一串入口加参数。

### 6.4 UI

`InteractTarget::Tree { species, action }` 三支（Fell / Harvest / Plant），
走既有的交互列表。名字走 HUD 文案键（`hud-interact-tree-oak` 等三条），与
**门那两条键同一档**——树不是内容物品，没有 `display_name_key`
（理由与 `interact_target_name` 里门那一段逐字同源）。

## 十四、验收（ADR 0031：真实内容 + 生产路径 + 端到端）
