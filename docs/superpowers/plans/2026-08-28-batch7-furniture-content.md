## 所有者裁定原文

> 建筑需要根据他的类型填入不同的家具，例如箱子，椅子，床，书柜等

## 范围：只做内容，不做摆放

**做**：家具的 `ItemDef` + `tools/ll-artgen` 生成的贴图 + 说得通的配方 + en/zh-CN 文案 + 测试。

**不做**（各有理由，不是遗漏）：

1. **不把家具摆进据点**。`Owner`（物品归属）至今没有裁定（`2026-08-28-session-handoff.md`
   第四节第 1 条）。现在摆进去，几百座据点的家具全是无主物，`Owner` 落地那天要写一次回填。
   `crates/ll-world/src/settlement.rs` 本批一个字不动。
2. **不做箱子的容器语义**。`GroundItemStack::contents` 今天唯一的消费者是尸体，而所有者已
   裁定把尸体改成「尸体与遗物平铺进同格掉落列表」——那等于取消尸体的容器身份。箱子才是
   `contents` 将来的正经消费者，但那要与尸体那批一起裁定。本批的箱子先是一件普通家具，
   这一点写在 `items.json5` 该条的注释里，免得后来人以为忘了。
3. **不改既有配方的 `required_station`**。三条锻造配方已经指向锻炉，不动。

## 加哪几件、为什么是这几件

判据是「填满住宅 / 作坊 / 仓库 / 酒馆四类建筑」，**不是凑齐一份家具目录**（YAGNI、ADR 0021）。
本体已有的锻炉占掉作坊那一格，其余六件按下表分工，每一类建筑都有至少两件说得通的东西可放：

| 家具 | 住宅 | 作坊 | 仓库 | 酒馆 |
|---|---|---|---|---|
| 锻炉（已有） | | ✓ | | |
| 橡木椅 | ✓ | ✓ | | ✓ |
| 橡木长桌 | ✓ | ✓ | | ✓ |
| 毛皮卧铺 | ✓ | | | ✓ |
| 橡木书柜 | ✓ | ✓ | | |
| 橡木酒桶 | | | ✓ | ✓ |
| 铁箍箱 | ✓ | | ✓ | |

刻意**不加**的：织机/鞣皮架这类「第二座作坊场地」。它要么当 `required_station`（那就得改
既有裁缝配方的前置，是一次玩法收紧，不该夹带在内容批次里），要么不当（那就是一件声明了
没人读的家具）。两条都不该现在做。

## 字段取值的判据

- **`furniture: true`**，`stack_limit: 1`（注册期硬校验：`define_one_item`）。
- **无耐久、无标签**：磨损只有两条通道，`ON_HIT` 走「持有者挨打时身上的装备」、`ON_USE` 走
  「装备着的工具/武器被使用」（`resolve.rs` 的 `wear_channels` 两处读取点）。**立在地上的
  家具一条都碰不到**，给它配耐久就是声明一个永远不变的数字。这与锻炉那条逐字同构。
- **无 `use_effect`**：`resolve_use_item` **无条件**产出 `ConsumeInventoryItem`——给床配一条
  「恢复耐力」会让用一次床就少一张床。
- **重量/价格**量级：全部低于锻炉（100000 / 40000），高于随身工具（铁匠锤 2800）。毛皮卧铺
  是全组最轻的一件，因为它就是一卷毛皮，不是木床架。

## 配方：只给材料说得通的两件

本体现有原材料只有铁锭、铁铆钉、亚麻布、皮革条、毛皮、草药束、生肉六种，**没有木料**。
所以：

- **毛皮卧铺** ← 裁缝（毛皮 ×4 + 亚麻布 ×3，工具骨针），与毛皮披风同形。
- **铁箍箱** ← 锻造（铁锭 ×2 + 铁铆钉 ×12 + 皮革条 ×2，场地锻炉、工具铁匠锤）。打的是箱子
  的铁箍与合页，木壳是配得上的部分。

其余四件（椅/桌/书柜/酒桶）**刻意不给配方**：给它们配方就得引出「木料」这个新原材料，那是
另一条内容线（树木系统尚未裁定，见交接第三节第 5 条）。先例是橡木圆盾——本体已有一件木器
没有配方。

## 贴图

六张全部走 `tools/ll-artgen` 生成，**走 `LooseOnlyEntry` 而不是 `placeholder.json`**：那份
JSON 是五个更早批次验收 demo 的冻结像素基准（`assets/atlas/placeholder.png`），新增条目会撑大
共享画布并把那批基准卷进来。气候批次的两种地形与上一批的两张 UI 贴图走的都是这条路。

条目名必须与内容 id 的本地名逐字一致（`lostland:oak_chair` → `oak_chair`）：
`ll_mod::asset_vfs` 把清单条目名与命名空间拼成图集条目名，渲染层
（`ll_game::surface_draw::placed_furniture_draws`）拿完整 ID 当查找键。**运行期名字带
`lostland:` 前缀**——这正是上一批五张 UI 贴图静默失效的根因，本批用一条端到端测试钉住。

## 门禁清单要不要加

`crates/ll-game/tests/atlas_coverage.rs` 那份手写清单是**地形**的（`all_base_terrains`）。
家具不是地形，不进那张表。但家具有和地形一模一样的失效方式（声明了却没有图 → 每帧静默退回
通用记号），所以本批在同一个文件里**新增一条家具专用的断言**，清单从**内容注册表现查**
（遍历 `ItemTable` 里 `furniture == true` 的每一条），不手抄——「加家具就要在这里加一行」这种
提醒本身就是那份地形清单的债，不该再欠第二笔。

## 验证

- 两条黄金基准预期**不变**：`determinism.rs` 的测试世界没有实体、没有地面物品，只走地形；
  `replay.rs` 的世界由 `setup` 手工构造，够不到 `ll-mod` 的注册表。实跑确认。
- `content_hash_of("lostland")` 预期**变**（那是它该变的）。
  `CONTENT_HASH_ALGORITHM_VERSION` **不动**——`write_item_fields` 的字段集合一个字没改。
- 新条目**追加在 `items.json5` 末尾**：物品在 `CONTENT_FILES` 里排在种族/文化/职业**之前**，
  插在中间会把其后每一条内容的 `ContentIndex` 整体平移（气候批次的教训）。
- ADR 0018：每条新断言逐条改坏跑一次，确认真的会红。
